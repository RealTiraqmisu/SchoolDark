# Use Case — SchoolDark (`app.html`, `leave-features.html`)

รวบรวมจากโค้ดจริงของโปรโตไทป์ใน `uxui-merged/schooldark/` ใช้เป็น input สร้าง Use Case Diagram
แบ่งเป็น 2 ระบบย่อย (System boundary) ตามไฟล์:

- **ระบบบริหารงานบุคคลและการลา** — `app.html` (+ `index.js`, `personnel.js`, `settings.js`)
- **ระบบการมาเรียน การลาเรียน และบัตรขออนุญาตนักเรียน** — `leave-features.html`

> หมายเหตุ: เป็น static prototype ยังไม่มีระบบล็อกอิน/สิทธิ์จริง บทบาทด้านล่างอนุมานจากข้อความใน UI,
> ตัวสลับบทบาท (role switcher) ในโมดูลการลาของ `app.html` และหน้าตั้งค่าผู้อนุมัติ ถ้าบทบาทไหนไม่ตรงกับ
> ที่ตั้งใจ ให้แก้ส่วน "Actors" ก่อนสร้าง diagram

## 5. Use Case Diagram (draw.io)

Diagram อยู่ที่ [`usecase.drawio`](usecase.drawio) — เปิดด้วย draw.io / diagrams.net แยก **1 หน้า (แท็บล่าง) ต่อ 1 ฟีเจอร์**
ตามหัวข้อ 2.x / 3.x ด้านบน รวม 7 หน้า แต่ละหน้าแสดงแค่ว่าฟีเจอร์นั้นทำอะไรได้บ้าง และใครเป็นคนใช้:
กรอบระบบ = ชื่อฟีเจอร์, use case เรียงเป็นคอลัมน์เดียว, actor อยู่ซ้าย/ขวา มีแค่เส้น actor ↔ use case

ใน diagram ตั้งใจ **ไม่ใส่** รหัส (A…, UC-…), เส้น «include» / «extend» และ generalization — รหัสและความสัมพันธ์เหล่านั้น
มีอยู่ในตารางของไฟล์นี้สำหรับอ้างอิง ส่วนขั้นตอนที่ระบบทำเอง (actor = "ระบบ" เช่น UC-P11, UC-S07) ไม่อยู่ใน diagram

ไฟล์ diagram สร้างจากตารางในไฟล์นี้ — ถ้าแก้ตาราง (เพิ่ม/ลบ use case หรือ actor) ให้แก้ diagram ตามด้วย

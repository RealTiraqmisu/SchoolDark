# ปรึกษา v2 (ยังไม่ลงมือ): หน้าของแคร์ค้าง + nav "ระเบิด" ตอนเปลี่ยนหน้า + ธีมสองฝั่งไม่เหมือนกัน

> ฉบับแก้ของข้อเสนอรอบแรก (ฉบับเดิมถูกลบทิ้งแล้วเพราะเข้าใจต้นเหตุผิด — ดูข้อ 1 ด้านล่าง) — เนยสดยืนยันว่าหน้าฝั่งตัวเอง
> (admission/settings/parent/apply) **ไม่ค้าง** ที่ค้างมีแค่ `schooldark/` ของแคร์ และตอนเปลี่ยนหน้า
> sidebar กาง/หุบวุ่นวาย ("ระเบิด") → เรื่อง Tailwind CDN/Lucide ในฉบับเดิมไม่ใช่ต้นเหตุ ตัดออก

## 1. ทำไม nav ของแคร์ "ระเบิด" ตอนเปิด/เปลี่ยนหน้า (ต้นเหตุหลัก)
ตอนโหลด `schooldark/app.html` มีการสั่งกาง/หุบกลุ่มเมนู **3–4 รอบติดกัน** และทุกรอบมี animation
(`.submenu` ใน `shared/cross-nav.css` มี `transition: grid-template-rows 180ms`):
1. `shared/cross-nav.js` สร้าง sidebar แล้วกางกลุ่มของหน้าปัจจุบัน
2. `schooldark/app.js` (DOMContentLoaded) เรียก `navigate('dashboard', …)` → หุบทุกกลุ่ม แล้วกางกลุ่มแดชบอร์ด
3. `schooldark/settings.js` (DOMContentLoaded) เรียก `navigateToView("general")` ทับ → กางกลุ่ม "ตั้งค่า" แทน
   (audit ข้อ 4 ข้อ 7 — บั๊ก: เปิดมาแล้วไปโผล่หน้าตั้งค่า)
4. ถ้ามาจากลิงก์หน้าอื่น (deep-link `#m=..&v=..`) `cross-nav.js` คลิกเมนูเป้าหมายอีกรอบ → กาง/หุบอีก

`leave-features.html` แบบเดียวกัน (มี logic กาง/หุบของตัวเองท้ายไฟล์) → เห็นเมนูเด้งเปิด-ปิดหลายทีตอนโหลด

## 2. ทำไมหน้าของแคร์ค้าง
- `app.html`/`leave-features.html` โหลด xlsx (~900KB) + Chart.js แบบ**รอให้เสร็จ**ใน `<head>` → จอขาวจนกว่าจะโหลดเสร็จ
- ไฟล์ใหญ่ (`leave-features.html` 474KB, `app.html` 250KB), SVG sprite ยาวอยู่ก่อน sidebar ใน `leave-features.html`
- `@import` ฟอนต์ใน `app.css`, `.glass-card` เงาใหญ่+transition, แดชบอร์ดการมาเรียนคำนวณหนัก (ครบใน audit ข้อ 4)

## 3. แนวทางแก้ (แยกของใครของมัน)
**`shared/` (เนยสดทำได้ ไม่แตะ JS ของแคร์)**
- ปิด animation ของ sidebar ช่วงโหลดหน้า: class `xnav-preload` บน `<html>` ตั้งแต่ `cross-nav.js` เริ่ม →
  `html.xnav-preload .sidebar * { transition: none !important }` → เอาออกหลังโหลด + deep-link เสร็จ (2 เฟรม)
  → เมนูไปอยู่สถานะสุดท้ายทันที ผู้ใช้กดเองยังมี animation ปกติ

**แคร์ (`schooldark/`)**
- ลบ `navigateToView("general")` ตอนโหลดใน `settings.js` (ต้นเหตุข้อ 1.3)
- lazy-load xlsx/Chart.js (โหลดตอนกด export/เปิดแดชบอร์ด)
- ที่เหลือตาม audit ข้อ 4

## 4. ธีมสองฝั่ง (ต้องตกลงกับแคร์)
- CSS ไม่ใช่ชุดเดียวกัน ใช้ร่วมแค่ `shared/cross-nav.css` — แคร์: `app.css` มีตัวแปร CSS อยู่แล้ว,
  เนยสด: Tailwind CDN + `tailwind-config.js` (hex ตรงๆ)
- ทางออก: `shared/tokens.css` ตัวแปรกลาง + ตกลงโครงหน้า (หัวหน้า/ความกว้าง/การ์ด) ลองฝั่งละ 1 หน้าก่อน
- ปุ่มสลับธีมเก่า/ใหม่: คุ้มถ้าสลับแค่ระดับ token (`<html data-theme>` + localStorage, ปุ่มท้าย sidebar)
  สลับโครงเลย์เอาต์ไม่ได้ และควรเป็นของชั่วคราว

## 5. คำถามคุยกับแคร์พรุ่งนี้
1. ให้เนยสดแก้ `shared/` ปิด animation ตอนโหลดได้เลยไหม (กระทบ sidebar ทุกหน้าของแคร์)
2. แคร์แก้บั๊ก navigate ซ้ำ + lazy-load xlsx/Chart.js เอง หรือให้เนยสดช่วย
3. ธีม: ยึดฝั่งไหนเป็นหลัก + เอาปุ่มสลับธีมไว้เทียบก่อนไหม
4. ใครเป็นเจ้าของ `shared/tokens.css`

## วิธีตรวจ (ตอนลงมือจริง)
- เปิด `schooldark/app.html` แล้วกดข้ามไป `leave-features.html`: sidebar ไม่กาง/หุบให้เห็น, เปิดมาอยู่แดชบอร์ด
- DevTools Performance: ไม่มีจอขาวยาวจาก xlsx/Chart.js; หน้าของเนยสดทำงานเหมือนเดิม

## 6. ข้อตัดสินใจเพิ่ม (2026-09-29, เนยสด) — ข้อนี้มาทีหลัง ถ้าขัดกับข้อ 1–5 ให้ยึดข้อนี้
- **ของแคร์ที่แก้แล้วไม่กระทบหน้าบ้าน (ผู้ใช้ไม่เห็นหน้าตาเปลี่ยน) → แก้ไปเลยได้** ไม่ต้องรอแคร์ เพื่อให้เป็นมาตรฐานเดียวกัน
  (คำถามข้อ 5.1 และ 5.2 จึงไม่ต้องถามแล้ว):
  - บั๊ก navigate ซ้ำ (`settings.js` `navigateToView("general")` ตอนโหลด)
  - lazy-load xlsx/Chart.js, `@import` ฟอนต์ → `<link>`, Chart.js `animation:false`
  - debounce ช่องค้นหา, cache ผล `sdCompute()`/`getAttendance()`
  - ปิด animation sidebar ช่วงโหลด (`shared/`)
  - **ยังไม่แตะ**: อะไรที่หน้าตาเปลี่ยน (เช่นเงา `.glass-card`, สี, เลย์เอาต์) → รอเรื่องธีม
- **ธีม**: เนยสดจะถามแคร์ก่อน แต่ตั้งใจเสนอให้ **ใช้ธีมฝั่งเนยสด (Tailwind) เป็นมาตรฐาน** เพราะไม่แลค
- **ไม่ compile อะไรทั้งนั้น** — ใช้ Tailwind CDN แบบที่เป็นอยู่ต่อไป (กฎ "ห้าม build" ใน `admission/AGENTS.md` ยังมีผล)
- **อาจแยกไฟล์ของแคร์**: เช่นย้าย inline script/CSS ของ `leave-features.html` (474KB) / `app.html` (250KB) ออกเป็นไฟล์ `.js`/`.css`
- **คู่มือนำทางให้แคร์**: ทุกครั้งที่แก้ไฟล์ของแคร์ ต้องบันทึกลง `schooldark/CHANGES-FOR-CARE.md` (ไฟล์ใหม่ อยู่ในโฟลเดอร์ของแคร์ให้เห็นง่าย)
  รูปแบบต่อรายการ: วันที่ · ไฟล์/ฟังก์ชัน · แก้อะไร · ทำไม · หน้าตาเปลี่ยนไหม · ถ้าอยากย้อนต้องทำอะไร
  + ลิงก์ไว้บรรทัดบนสุดของ `schooldark/CLAUDE.md` ให้แคร์ (และ Claude ของแคร์) เจอ

### ขยายความ: "ใครเป็นเจ้าของ `shared/tokens.css`" (คำถาม 5.4) หมายถึงอะไร
- `shared/tokens.css` คือไฟล์ใหม่ (ยังไม่มีจริง) ที่เก็บ **ค่ากลางของหน้าตา** ไว้จุดเดียวเป็นตัวแปร CSS เช่น
  `--color-primary: #4f46e5;` `--radius-card: 12px;` `--font-body: 'Sarabun';` แล้วทั้งฝั่งเนยสด
  (`tailwind-config.js` ชี้สีไปที่ `var(--color-primary)`) และฝั่งแคร์ (`app.css` ใช้ `var(--color-primary)`)
  อ่านค่าจากไฟล์นี้ → **แก้ค่าเดียว ทั้งสองระบบเปลี่ยนพร้อมกัน** = ธีมเดียวกันจริง
- เพราะแก้ทีเดียวกระทบทั้งคู่ จึงต้องตกลงว่า **ใครมีสิทธิ์แก้/อนุมัติ**:
  - แบบ A: เนยสดเป็นเจ้าของ (ธีมยึดฝั่งเนยสดอยู่แล้ว) — แคร์อยากเปลี่ยนค่าไหนต้องบอกเนยสดก่อน
  - แบบ B: เป็นของกลาง — ใครจะแก้ต้องแจ้งอีกฝ่ายทุกครั้ง (เหมือนกฎของ `shared/` ใน `CLAUDE.md` ตอนนี้)
- ถ้าไม่ตกลงก่อน: เช่นแคร์เปลี่ยน `--color-primary` ให้หน้าตัวเองสวยขึ้น → ปุ่มทุกหน้าของเนยสดเปลี่ยนสีตามโดยไม่รู้ตัว
- คำแนะนำ: **แบบ A** — บันทึกผลที่ตกลงไว้ใน `CLAUDE.md` (root) หัวข้อ "ผู้พัฒนาและขอบเขตความรับผิดชอบ"

### ผลคุยกับแคร์ + ที่ลงมือแล้ว (2026-09-29, เนยสด) — ข้อนี้ใหม่สุด ถ้าขัดกับข้างบนให้ยึดข้อนี้
- **ธีม: คุยกับแคร์แล้ว → ใช้ธีมฝั่งเนยสด (Tailwind) เป็นมาตรฐาน** แต่ **ค่อย ๆ แก้ทีละหน้า/ทีละส่วนตามที่เนยสดสั่งเท่านั้น**
  ห้าม auto ทำทั้งระบบเองจนกว่าเนยสดจะบอกว่ามั่นใจ (Claude ไม่ต้องเริ่มเปลี่ยนธีมเองเมื่อไม่ได้สั่ง)
- เจ้าของ `shared/tokens.css`: **ยังไม่ได้ตกลง** (คำแนะนำเดิมคือแบบ A เนยสดเป็นเจ้าของ) และไฟล์นี้ยังไม่ถูกสร้าง
- รอบ "หน้าตาไม่เปลี่ยน" **ทำเสร็จแล้ว** ครบข้อ 6: preload ปิด animation เมนู, ลบ `navigateToView("general")`,
  แก้ `navigateToView` ชื่อซ้ำ (บั๊กใหม่ที่เจอ), lazy-load xlsx/Chart.js, `@import`→`<link>`, Chart `animation:false`,

  และ **แยก `leave-features.html` เป็น `.html`/`.css`/`.js`** — รายละเอียดครบใน `schooldark/CHANGES-FOR-CARE.md`
  (`app.html` ไม่มี inline script/CSS ให้แยก)

### คำตอบปรึกษา layout (2026-09-29): ตรงกลางเว้นข้าง vs เต็มจอ
- **คำแนะนำ**: 2 แบบตามชนิดหน้า — หน้าอ่าน/ฟอร์ม = ตรงกลางจำกัดกว้าง ~1280px (ตาไม่ต้องวิ่งไกลบนจอกว้าง), หน้าตาราง/แดชบอร์ด/ปฏิทิน = เต็มพื้นที่เนื้อหา
  (ตารางไม่ต้องเลื่อนแนวนอน) ลด `max-w-*` ที่กระจายหลายขนาด (2xl/4xl/6xl/1400) ให้เหลือ 2 แบบ
- **ทดลองแล้ว 2 หน้า** (แบบ wide): `admission/students.html`, `admission/index.html` ผ่าน `shared/page-layout.css` (`.xpage--read`/`.xpage--wide`)
  วัดที่ 1920px: เนื้อหากว้าง ~1610px เต็มพื้นที่ข้าง sidebar ส่วน `admission/settings.html` (ยัง 1400) อยู่กลางเว้นข้าง; ที่ 1366px ไม่ต่างกันเพราะ 1400 กว้างกว่าพื้นที่อยู่แล้ว
- **ขั้นต่อไป**: เนยสดดูผลบนจอจริง แล้วค่อยบอกว่าจะขยายไปหน้าไหน (และหน้าไหนใช้ `--read`)

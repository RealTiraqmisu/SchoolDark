# Use Case Description — หมวดที่ 1: งานทะเบียนนักเรียน

หมวดนี้ครอบคลุมงานของฝ่ายทะเบียนที่ดูแลข้อมูลนักเรียนตั้งแต่รับเข้าสู่ทะเบียนจนถึงจบการศึกษาหรือพ้นสภาพ
รวมถึงศิษย์เก่า ซึ่งเป็นนักเรียนที่มีสถานะสำเร็จการศึกษาอยู่ในทะเบียนเดียวกัน

> Actor, Stakeholder และกฎธุรกิจร่วม (`BR-xx`) ดูที่ [`use-case-description-index.md`](./use-case-description-index.md)

---

## UC-REG-01 จัดการข้อมูลนักเรียนและศิษย์เก่า

| หัวข้อ                        | รายละเอียด                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**             | จัดการข้อมูลนักเรียนและศิษย์เก่า                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **ID**                        | UC-REG-01                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Scenario**                  | เปิดภาคเรียนใหม่ ฝ่ายทะเบียนได้รับเอกสารนักเรียนที่ขอย้ายเข้าจากโรงเรียนอื่น 3 ราย และได้รับไฟล์รายชื่อศิษย์เก่ารุ่นปี 2566 จากฝ่ายวิชาการ จึงต้องบันทึกเข้าสู่ทะเบียนนักเรียนของโรงเรียน                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Trigger Event**             | ฝ่ายทะเบียนได้รับเอกสารรับนักเรียนย้ายเข้า หรือได้รับไฟล์รายชื่อนักเรียนหรือศิษย์เก่าที่ต้องนำเข้าระบบ หรือพบรายการซ้ำหรือผิดพลาดที่ต้องลบออกจากทะเบียน                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Brief Description**         | บันทึกนักเรียนเข้าสู่ทะเบียนโดยตรงโดยไม่ผ่านกระบวนการรับสมัคร ทั้งแบบรายบุคคลและแบบนำเข้าเป็นชุดจากไฟล์ ซึ่งรองรับทั้งนักเรียนปัจจุบันและศิษย์เก่าในไฟล์เดียวกัน รวมถึงการลบรายการที่ไม่ถูกต้องออกจากระบบ                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Actor(s)**                  | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Related Use Cases**         | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — ต้องเข้าถึงรายการทะเบียนก่อนจึงจะเรียกใช้คำสั่งจัดการได้<br>«extend» UC-REG-03 แก้ไขข้อมูลนักเรียน — แก้ไขข้อมูลที่บันทึกไว้แล้วในภายหลัง<br>เกี่ยวข้องกับ UC-SET-REG-02 ตั้งค่าคอลัมน์นักเรียน — โครงข้อมูลของไฟล์นำเข้าอ้างอิงฟิลด์ชุดเดียวกัน                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Stakeholders**              | นักเรียน, ผู้ปกครอง, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน, หน่วยงานต้นสังกัด                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Pre-Conditions**            | 1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. ระบบมีข้อมูลโครงห้องเรียนของโรงเรียนครบตาม BR-11 และมีแผนการเรียนอย่างน้อย 1 แผน<br>3. กรณีนำเข้าเป็นชุด ฝ่ายทะเบียนต้องมีไฟล์ข้อมูลที่มีโครงสร้างตรงตามที่ระบบกำหนด                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Post-Conditions**           | 1. นักเรียนรายใหม่ถูกบันทึกลงทะเบียนนักเรียน พร้อมได้รับรหัสใบสมัครและรหัสนักเรียนตาม BR-01 และ BR-02<br>2. นักเรียนที่บันทึกผ่าน Use Case นี้มีสถานะตั้งต้นเป็น "กำลังศึกษา" ทันที โดยไม่ต้องผ่านขั้นตอนรับสมัคร<br>3. ข้อมูลที่นำเข้าแบบศิษย์เก่าได้สถานะ "สำเร็จการศึกษา"<br>4. ทุกการเปลี่ยนแปลงถูกบันทึกลงประวัติการดำเนินการ พร้อมชื่อผู้ดำเนินการและเวลา<br>5. รายการทะเบียนและจำนวนนักเรียนต่อห้องเรียนถูกปรับให้ตรงกับข้อมูลใหม่ทันที                                                                                                                                                                                                                                                                                                                                                                                            |
| **Basic Flow of Events**      | 1. ฝ่ายทะเบียนเข้าสู่รายการทะเบียนนักเรียน<br>2. ฝ่ายทะเบียนเลือกเพิ่มนักเรียนใหม่<br>3. ฝ่ายทะเบียนระบุประเภทระหว่างนักเรียนใหม่กับนักเรียนที่ย้ายเข้าจากสถานศึกษาอื่น<br>4. ฝ่ายทะเบียนระบุข้อมูลประวัติพื้นฐาน ระดับชั้น ห้องเรียน และแผนการเรียนของนักเรียน<br>5. ระบบตรวจสอบข้อมูลที่จำเป็น และแสดงสรุปให้ตรวจสอบก่อนยืนยัน<br>6. ฝ่ายทะเบียนยืนยันการเพิ่มนักเรียน<br>7. ระบบบันทึกนักเรียนลงทะเบียน ออกรหัสใบสมัครและรหัสนักเรียนให้อัตโนมัติ กำหนดสถานะเป็น "กำลังศึกษา" บันทึกประวัติการดำเนินการ และแจ้งผลสำเร็จ                                                                                                                                                                                                                                                                                                                |
| **Alternate/Exception Flows** | **Alt Flow 3a — นำเข้าข้อมูลเป็นชุดจากไฟล์:** ฝ่ายทะเบียนเลือกนำเข้าข้อมูลนักเรียนจากไฟล์ที่มีโครงสร้างตรงตามที่ระบบกำหนด โดยระบุในไฟล์ได้ว่าแต่ละรายการเป็นนักเรียนปัจจุบันหรือศิษย์เก่า ระบบดาวน์โหลดไฟล์ต้นแบบให้ใช้อ้างอิงได้ เมื่อเลือกไฟล์แล้วระบบตรวจสอบและบันทึกข้อมูลรายรายการ แจ้งผลสำเร็จ<br><br>**Alt Flow 6a — ลบข้อมูลนักเรียน:** ฝ่ายทะเบียนเลือกลบนักเรียนออกจากระบบ ระบบแสดงคำเตือนว่าการลบจะถอนสถานะการเป็นนักเรียนอย่างถาวรและไม่สามารถกู้คืนได้ เมื่อยืนยันแล้วระบบลบข้อมูล บันทึกประวัติ และแจ้งผลสำเร็จ<br><br>**Exception 5a — ข้อมูลที่จำเป็นไม่ครบถ้วน:** ระบบแจ้งว่ายังไม่ได้ระบุชื่อและนามสกุลของนักเรียน และไม่บันทึกจนกว่าจะกรอกครบ<br><br>**Exception A3a — ไฟล์นำเข้าผิดรูปแบบหรือมีข้อมูลไม่ถูกต้อง:** ระบบหยุดการนำเข้า แจ้งข้อผิดพลาดเป็นรายการ และไม่บันทึกข้อมูลใดๆ ลงระบบจนกว่าจะแก้ไขไฟล์ให้ถูกต้อง |

## UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ดูข้อมูลนักเรียนและศิษย์เก่า |
| **ID** | UC-REG-02 |
| **Scenario** | ครูประจำชั้นต้องการรายชื่อนักเรียนในห้องตนเองเรียงตามเลขที่เพื่อเตรียมใบเช็คชื่อ ขณะที่ฝ่ายทะเบียนต้องการค้นหาศิษย์เก่ารายหนึ่งจากเลขประจำตัวประชาชนเพื่อออกหนังสือรับรอง |
| **Trigger Event** | ผู้ใช้เปิดรายการทะเบียนนักเรียน หรือปรับเงื่อนไขการค้นหาและกรองรายการ |
| **Brief Description** | ค้นหา กรอง เรียงลำดับ และเรียกดูรายชื่อนักเรียนทั้งโรงเรียนในหน้าจอเดียว ครอบคลุมทั้งนักเรียนปัจจุบันและศิษย์เก่า พร้อมเจาะดูรายละเอียดรายบุคคล |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครู, ครูประจำชั้น (Primary) |
| **Related Use Cases** | «extend» UC-REG-03, UC-REG-04, UC-REG-05, UC-REG-06, UC-REG-07, UC-REG-08 — ทุก Use Case เหล่านี้เริ่มต้นจากรายการที่กรองหรือเลือกไว้ใน Use Case นี้<br>เกี่ยวข้องกับ UC-SET-REG-02 ตั้งค่าคอลัมน์นักเรียน — รายการเรนเดอร์คอลัมน์ตามค่าที่ตั้งไว้ |
| **Stakeholders** | นักเรียน, ผู้ปกครอง, ครูที่ปรึกษา, ฝ่ายวิชาการ |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบในบทบาทที่มีสิทธิ์ดูข้อมูลนักเรียน<br>2. ระบบมีข้อมูลนักเรียนในทะเบียนอย่างน้อย 1 รายการ<br>3. ครูประจำชั้นเห็นเฉพาะนักเรียนในห้องที่ตนรับผิดชอบ ส่วนครูทั่วไป ฝ่ายทะเบียน และผู้ดูแลระบบเห็นข้อมูลทั้งโรงเรียน |
| **Post-Conditions** | 1. ระบบแสดงรายชื่อนักเรียนที่ตรงตามเงื่อนไข พร้อมจำนวนผลลัพธ์<br>2. เงื่อนไขการค้นหา การเรียงลำดับ และจำนวนรายการต่อหน้าที่ตั้งไว้ล่าสุดถูกจดจำไว้สำหรับการใช้งานครั้งถัดไป<br>3. ไม่มีการเปลี่ยนแปลงข้อมูลนักเรียนใดๆ เนื่องจาก Use Case นี้เป็นการอ่านอย่างเดียว |
| **Basic Flow of Events** | 1. ผู้ใช้เปิดรายการทะเบียนนักเรียน<br>2. ระบบแสดงรายการนักเรียนที่มีสถานะกำลังศึกษาเป็นค่าเริ่มต้น พร้อมเงื่อนไขการกรองที่จดจำไว้ล่าสุด<br>3. ผู้ใช้ระบุเงื่อนไขการค้นหาตามคำค้น ปีการศึกษาและภาคเรียน ระดับชั้น ห้องเรียน แผนการเรียน หรือสถานะของนักเรียน<br>4. ระบบกรองรายชื่อตามเงื่อนไขที่ระบุ โดยใช้ห้องเรียนจริงของนักเรียนตาม BR-12<br>5. ผู้ใช้เลือกลำดับการเรียงข้อมูลตามที่ต้องการ<br>6. ระบบแสดงผลลัพธ์พร้อมจำนวนรายการทั้งหมดและการแบ่งหน้า<br>7. ผู้ใช้เลือกนักเรียนรายหนึ่งเพื่อดูรายละเอียด<br>8. ระบบแสดงประวัติ ความคืบหน้าของกระบวนการคัดเลือก และข้อมูลของนักเรียนรายนั้นแบ่งเป็นหมวด |
| **Alternate/Exception Flows** | **Alt Flow 4a — ดูรายชื่อศิษย์เก่า:** ผู้ใช้เลือกกรองด้วยสถานะสำเร็จการศึกษา ระบบแสดงเฉพาะศิษย์เก่าพร้อมจำนวนที่นับได้จริง<br><br>**Alt Flow 6a — เจาะดูเฉพาะห้องเรียน:** เมื่อผู้ใช้เลือกดูเฉพาะระดับชั้นหรือห้องเรียนหนึ่ง ระบบเปลี่ยนการเรียงลำดับเป็นเลขที่ในห้องให้อัตโนมัติเพื่อความสะดวก และคืนค่าการเรียงเดิมเมื่อกลับไปดูทั้งโรงเรียน<br><br>**Alt Flow 3a — ล้างเงื่อนไขทั้งหมด:** ผู้ใช้เลือกล้างตัวกรองทั้งหมด ระบบคืนค่าเงื่อนไขการค้นหาทั้งหมดกลับเป็นค่าเริ่มต้น<br><br>**Exception 6a — ไม่พบข้อมูลตามเงื่อนไข:** ระบบแจ้งว่าไม่พบนักเรียนที่ตรงตามเงื่อนไข พร้อมทางเลือกให้ล้างตัวกรองทั้งหมด |

## UC-REG-03 แก้ไขข้อมูลนักเรียน

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | แก้ไขข้อมูลนักเรียน |
| **ID** | UC-REG-03 |
| **Scenario** | ผู้ปกครองของนักเรียนคนหนึ่งเปลี่ยนเบอร์โทรศัพท์และย้ายที่อยู่ ครูประจำชั้นจึงแจ้งฝ่ายทะเบียนให้ปรับปรุงข้อมูลในทะเบียนให้ตรงกับเอกสารจริง |
| **Trigger Event** | ผู้ใช้เลือกแก้ไขข้อมูลของนักเรียนรายหนึ่งจากรายการทะเบียนหรือจากรายละเอียดนักเรียน |
| **Brief Description** | ปรับปรุงข้อมูลประวัติส่วนตัว ข้อมูลติดต่อและผู้ปกครอง และแผนการศึกษาของนักเรียนรายบุคคล โดยระบบบันทึกร่องรอยว่าใครเป็นผู้แก้ไขล่าสุดและแก้ไขเมื่อใด |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครูประจำชั้น (Primary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — เป็นจุดเริ่มต้นของ Use Case นี้<br>เกี่ยวข้องกับ UC-SET-REG-01 ตั้งค่าฟอร์มนักเรียน — ฟิลด์และความจำเป็นของแต่ละช่องมาจากการตั้งค่านั้น<br>ไม่รวมการเปลี่ยนห้องเรียนและระดับชั้น ซึ่งอยู่ใน UC-REG-04 และไม่รวมการเปลี่ยนสถานะ ซึ่งอยู่ใน UC-REG-05 |
| **Stakeholders** | นักเรียน, ผู้ปกครอง, ครูที่ปรึกษา, นายทะเบียน |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบในบทบาทผู้ดูแลระบบ ฝ่ายทะเบียน หรือครูประจำชั้น<br>2. นักเรียนที่จะแก้ไขมีอยู่จริงในระบบ<br>3. ครูประจำชั้นแก้ไขได้เฉพาะนักเรียนในห้องที่ตนรับผิดชอบ |
| **Post-Conditions** | 1. ข้อมูลนักเรียนถูกปรับปรุงตามที่ระบุ<br>2. ระบบบันทึกชื่อผู้แก้ไขล่าสุดและวันเวลาที่แก้ไขไว้กับข้อมูลนักเรียน<br>3. ข้อมูลที่แก้ไขปรากฏในรายการทะเบียน รายละเอียดนักเรียน และเอกสารที่ส่งออกในภายหลังทันที |
| **Basic Flow of Events** | 1. ผู้ใช้เลือกแก้ไขข้อมูลของนักเรียนที่ต้องการ<br>2. ระบบแสดงข้อมูลเดิมของนักเรียน แบ่งเป็นข้อมูลส่วนบุคคล ข้อมูลติดต่อและผู้ปกครอง และแผนการศึกษา<br>3. ระบบแสดงข้อมูลสถานะที่อ่านอย่างเดียวประกอบด้วยรหัสประจำตัว วันที่เข้าเรียน ห้องเรียนปัจจุบัน ความครบถ้วนของเอกสาร และผู้แก้ไขล่าสุด<br>4. ผู้ใช้ปรับปรุงข้อมูลที่ต้องการแก้ไข<br>5. ผู้ใช้ยืนยันการบันทึก<br>6. ระบบตรวจสอบข้อมูลที่จำเป็น บันทึกการเปลี่ยนแปลงพร้อมประทับชื่อผู้แก้ไขและเวลาที่แก้ไข และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 3a — เปิดดูเลขบัตรประจำตัวประชาชน:** ผู้ใช้เลือกเปิดดูเลขประจำตัวประชาชนที่ปิดบังไว้ตาม BR-13 ระบบแสดงเลขเต็มชั่วคราวและปิดบังกลับเมื่อออกจากช่องนั้น<br><br>**Alt Flow 5a — ยกเลิกการแก้ไข:** ผู้ใช้ยกเลิกก่อนบันทึก ระบบทิ้งการเปลี่ยนแปลงทั้งหมดและกลับไปยังรายการทะเบียนโดยไม่บันทึกสิ่งใด<br><br>**Exception 6a — ข้อมูลที่จำเป็นไม่ครบถ้วน:** ระบบแจ้งว่าข้อมูลบังคับ ได้แก่ ชื่อ นามสกุล และอีเมลผู้ปกครอง ยังไม่ครบ และคงหน้าแก้ไขไว้พร้อมข้อมูลที่ระบุไว้เดิม<br><br>**Exception 1a — ไม่พบข้อมูลนักเรียน:** ระบบแจ้งว่าไม่พบข้อมูลนักเรียนในระบบ และไม่แสดงแบบฟอร์มแก้ไข |

## UC-REG-04 ย้ายห้องเรียน เลื่อนชั้นนักเรียน

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ย้ายห้องเรียน เลื่อนชั้นนักเรียน |
| **ID** | UC-REG-04 |
| **Scenario** | สิ้นปีการศึกษา ฝ่ายทะเบียนต้องเลื่อนชั้นนักเรียนทั้งโรงเรียนขึ้นหนึ่งระดับ ยกเว้นนักเรียนบางคนที่ติด 0 และต้องบันทึกให้นักเรียนชั้นสุดท้ายของแต่ละช่วงชั้นสำเร็จการศึกษา นอกจากนี้ระหว่างเทอมยังมีนักเรียนขอสลับห้องเรียนภายในระดับชั้นเดียวกัน |
| **Trigger Event** | สิ้นปีการศึกษาถึงกำหนดเลื่อนชั้น หรือได้รับคำร้องขอย้ายห้องเรียนที่ผ่านการอนุมัติแล้ว |
| **Brief Description** | ปรับโครงสร้างชั้นเรียนของนักเรียน 2 รูปแบบ คือ ย้ายห้องเรียนภายในระดับชั้นเดียวกัน และเลื่อนระดับชั้นขึ้นหนึ่งปีพร้อมบันทึกสำเร็จการศึกษาสำหรับชั้นสุดท้าย โดยมีขั้นตอนตรวจสอบตัวอย่างและการยกเว้นรายบุคคลก่อนบันทึกจริง |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — เลือกขอบเขตนักเรียนจากรายการทะเบียน<br>«extend» UC-REG-08 ส่งออก ปพ.1 และ ปพ.2 — นักเรียนที่สำเร็จการศึกษาจาก Use Case นี้คือกลุ่มเป้าหมายของเอกสาร ปพ.2<br>เกี่ยวข้องกับ UC-REG-05 จัดการนักเรียนลาออก — นักเรียนที่ลาออกแล้วจะไม่เข้าเกณฑ์เลื่อนชั้น |
| **Stakeholders** | นักเรียน, ผู้ปกครอง, ครูประจำชั้น, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน |
| **Pre-Conditions** | 1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. มีนักเรียนสถานะกำลังศึกษาอยู่ในขอบเขตที่เลือกอย่างน้อย 1 คน<br>3. กรณีย้ายห้องเรียน นักเรียนที่เลือกต้องอยู่ในระดับชั้นเดียวกันทั้งหมดตาม BR-05<br>4. ผลการเรียนปลายปีได้รับการอนุมัติจากฝ่ายวิชาการแล้วในกรณีเลื่อนชั้น |
| **Post-Conditions** | 1. นักเรียนที่ย้ายห้องมีห้องเรียนใหม่ตามที่กำหนด และนับรวมในจำนวนคนของห้องปลายทางทันที<br>2. นักเรียนที่เลื่อนชั้นมีระดับชั้นสูงขึ้นหนึ่งปี พร้อมห้องเรียนในระดับชั้นใหม่ที่คงหมายเลขห้องเดิม<br>3. นักเรียนชั้นสุดท้ายของแต่ละช่วงชั้นที่ผ่านเกณฑ์มีสถานะเปลี่ยนเป็นสำเร็จการศึกษาตาม BR-07 และกลายเป็นศิษย์เก่า<br>4. นักเรียนที่ถูกยกเว้นคงระดับชั้น ห้องเรียน และสถานะเดิมไว้ทุกประการ<br>5. ระบบบันทึกประวัติการดำเนินการพร้อมจำนวนคนที่เลื่อนชั้น จบการศึกษา และถูกยกเว้น |
| **Basic Flow of Events** | 1. ฝ่ายทะเบียนเลือกดำเนินการเลื่อนชั้นเรียนและบันทึกสำเร็จการศึกษา<br>2. ระบบรวบรวมนักเรียนสถานะกำลังศึกษาทั้งหมดเป็นรายชื่อตั้งต้นตาม BR-06 ว่าทุกคนเลื่อนชั้นโดยปริยาย<br>3. ฝ่ายทะเบียนตรวจสอบรายชื่อและยกเว้นเฉพาะนักเรียนที่ไม่ผ่านเกณฑ์<br>4. ระบบแสดงสรุปจำนวนที่เลื่อนชั้น จำนวนที่จบการศึกษา และจำนวนที่ถูกยกเว้นให้ตรวจสอบ<br>5. ฝ่ายทะเบียนยืนยันการดำเนินการ<br>6. ระบบปรับระดับชั้นและห้องเรียนของผู้ที่เลื่อนชั้น เปลี่ยนสถานะผู้ที่จบเป็นสำเร็จการศึกษา บันทึกประวัติ และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 1a — เลื่อนชั้นเฉพาะนักเรียนที่เลือก:** ฝ่ายทะเบียนเลือกนักเรียนบางส่วนในรายการทะเบียนก่อน แล้วดำเนินการเลื่อนชั้นเฉพาะกลุ่มที่เลือกไว้<br><br>**Alt Flow B — ย้ายห้องเรียนภายในระดับชั้นเดียวกัน:** ฝ่ายทะเบียนเลือกย้ายห้องเรียนแบบยกทั้งห้องหรือเฉพาะนักเรียนที่เลือกไว้ ระบุห้องเรียนปลายทางในระดับชั้นเดียวกัน ระบบแสดงตัวอย่างการเปลี่ยนแปลงให้ตรวจสอบก่อนยืนยัน แล้วบันทึกห้องเรียนใหม่ให้นักเรียนที่เลือก<br><br>**Exception 5a — ไม่มีรายชื่อที่ต้องดำเนินการ:** หากฝ่ายทะเบียนยกเว้นนักเรียนทุกคน ระบบแจ้งว่าไม่มีรายชื่อที่ต้องเลื่อนชั้นและไม่ดำเนินการต่อ<br><br>**Exception B1a — เลือกนักเรียนข้ามระดับชั้น:** เมื่อเลือกนักเรียนจากหลายระดับชั้นแล้วสั่งย้ายห้อง ระบบปฏิเสธการดำเนินการ อธิบายว่าเมนูนี้ใช้สลับห้องภายในระดับชั้นเดียวกันเท่านั้น และแนะนำให้ใช้การเลื่อนชั้นเรียนแทนหากต้องการเปลี่ยนระดับชั้น |

## UC-REG-05 จัดการนักเรียนลาออก

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | จัดการนักเรียนลาออก |
| **ID** | UC-REG-05 |
| **Scenario** | ผู้ปกครองของนักเรียนสองคนย้ายภูมิลำเนาไปต่างจังหวัด จึงยื่นเรื่องขอย้ายไปเรียนที่โรงเรียนใหม่ ส่วนนักเรียนอีกคนขอพักการเรียนหนึ่งภาคเรียนเนื่องจากปัญหาสุขภาพ ฝ่ายทะเบียนต้องปรับสถานะทั้งสามรายพร้อมบันทึกเหตุผล |
| **Trigger Event** | ฝ่ายทะเบียนได้รับคำร้องขอย้ายออก ลาออก พักการเรียน หรือได้รับคำสั่งให้นักเรียนพ้นสภาพ |
| **Brief Description** | เปลี่ยนสถานะนักเรียนที่ออกจากการเป็นนักเรียนปัจจุบันเป็นหนึ่งในสี่ประเภท ได้แก่ ย้ายโรงเรียน ลาออก พักการเรียน หรือพ้นสภาพ พร้อมระบุสถานศึกษาปลายทางและเหตุผล โดยมีขั้นตอนตรวจสอบตัวอย่างก่อนบันทึกจริง |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — ต้องเลือกนักเรียนจากรายการทะเบียนก่อนดำเนินการ<br>«extend» UC-REG-07 ส่งออกรายงานและสถิติ — ข้อมูลวันที่เปลี่ยนสถานะเป็นฐานของรายงานลาออก<br>เกี่ยวข้องกับ UC-REG-04 ย้ายห้องเรียน เลื่อนชั้นนักเรียน — นักเรียนที่ถูกปรับสถานะแล้วจะไม่เข้าเกณฑ์การเลื่อนชั้น |
| **Stakeholders** | นักเรียน, ผู้ปกครอง, ครูประจำชั้น, นายทะเบียน, โรงเรียนปลายทาง, หน่วยงานต้นสังกัด |
| **Pre-Conditions** | 1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. ฝ่ายทะเบียนต้องเลือกนักเรียนในรายการทะเบียนอย่างน้อย 1 คนก่อน<br>3. คำร้องหรือคำสั่งที่เกี่ยวข้องผ่านการอนุมัติจากผู้มีอำนาจแล้ว |
| **Post-Conditions** | 1. นักเรียนที่เลือกมีสถานะใหม่ตามประเภทที่ระบุ<br>2. ระบบบันทึกเหตุผลการดำเนินการ สถานศึกษาปลายทาง และวันเวลาที่เปลี่ยนสถานะไว้กับนักเรียนแต่ละคน<br>3. นักเรียนที่เปลี่ยนสถานะแล้วหลุดออกจากมุมมองกำลังศึกษา จำนวนคนของห้องเรียนลดลงตามจริง และไม่เข้าเกณฑ์การเลื่อนชั้นอีกต่อไป<br>4. ระบบบันทึกประวัติการดำเนินการพร้อมจำนวนคนและสถานะปลายทาง |
| **Basic Flow of Events** | 1. ฝ่ายทะเบียนเลือกนักเรียนที่ต้องการปรับสถานะจากรายการทะเบียน<br>2. ระบบแสดงคำสั่งที่ใช้ได้กับรายการที่เลือก พร้อมจำนวนนักเรียนที่เลือกไว้<br>3. ฝ่ายทะเบียนเลือกคำสั่งบันทึกการย้ายออก ลาออก หรือปรับสถานะ<br>4. ระบบแสดงรายชื่อนักเรียนที่จะดำเนินการ และให้ปรับรายชื่อได้ก่อนบันทึก<br>5. ฝ่ายทะเบียนระบุประเภทการออกจากสถานภาพนักเรียน ได้แก่ ย้ายไปสถานศึกษาอื่น ลาออก พักการเรียน หรือพ้นสภาพ พร้อมสถานศึกษาปลายทางและเหตุผลประกอบ<br>6. ระบบแสดงตัวอย่างการเปลี่ยนแปลงทั้งหมดให้ตรวจสอบก่อนยืนยัน<br>7. ฝ่ายทะเบียนยืนยันการดำเนินการ<br>8. ระบบบันทึกสถานะใหม่ เหตุผล สถานศึกษาปลายทาง และวันที่มีผล พร้อมบันทึกประวัติการดำเนินการ และแจ้งผลการบันทึก |
| **Alternate/Exception Flows** | **Alt Flow 5a — ตัดบางคนออกจากรายการ:** ฝ่ายทะเบียนเอานักเรียนบางคนออกจากรายการที่จะดำเนินการก่อนยืนยัน ระบบปรับจำนวนที่จะดำเนินการให้ตรงกับรายการที่เหลือ<br><br>**Exception 1a — ยังไม่ได้เลือกนักเรียน:** ระบบแจ้งว่าต้องเลือกนักเรียนอย่างน้อย 1 คนก่อนจึงจะดำเนินการได้<br><br>**Exception 7a — ไม่มีนักเรียนเหลือในรายการ:** หากฝ่ายทะเบียนเอานักเรียนออกจากรายการจนหมด ระบบแจ้งว่าไม่มีนักเรียนที่จะดำเนินการและไม่บันทึกสิ่งใด |

| **ID** | UC-REG-06 |
| **Scenario** | ครูประจำชั้นต้องการไฟล์ใบเช็คชื่อประจำห้องเพื่อนำไปพิมพ์ ส่วนฝ่ายทะเบียนต้องการไฟล์รายชื่อนักเรียนทั้งระดับชั้นแยกเป็นคนละไฟล์ตามห้อง เพื่อส่งให้ครูแต่ละห้อง |
| **Trigger Event** | ผู้ใช้ต้องการนำรายชื่อนักเรียนออกไปใช้นอกระบบ เช่น ทำใบรายชื่อ ใบเช็คชื่อ พิมพ์บัตรประจำตัว หรือส่งข้อมูลให้หน่วยงานต้นสังกัด |
| **Brief Description** | ส่งออกรายชื่อนักเรียนเป็นไฟล์ผ่านขั้นตอนเดียวที่เลือกได้ครบทั้งประเภทข้อมูล ขอบเขตที่จะส่งออก คอลัมน์ที่จะแสดง และรูปแบบไฟล์ รวมถึงการพิมพ์บัตรประจำตัวนักเรียนและการส่งข้อมูลไปยังหน่วยงานต้นสังกัด |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครู (Primary) · ระบบพิมพ์เอกสาร, ระบบ REGIS สช. (Secondary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — ขอบเขตการส่งออกอ้างอิงเงื่อนไขหรือรายชื่อที่เลือกไว้<br>เกี่ยวข้องกับ UC-SET-REG-02 ตั้งค่าคอลัมน์นักเรียน — รายการคอลัมน์ที่เลือกส่งออกได้มาจากการตั้งค่านั้น<br>เกี่ยวข้องกับ UC-REG-07 ส่งออกรายงานและสถิติ — ใช้ขั้นตอนส่งออกร่วมกัน |
| **Stakeholders** | ครูประจำชั้น, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน, หน่วยงานต้นสังกัด |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบในบทบาทที่มีสิทธิ์ดูข้อมูลนักเรียน<br>2. มีนักเรียนที่ตรงตามขอบเขตที่เลือกอย่างน้อย 1 คน<br>3. ต้องเลือกคอลัมน์ที่จะแสดงอย่างน้อย 1 คอลัมน์ |
| **Post-Conditions** | 1. ระบบสร้างไฟล์ตามรูปแบบและจำนวนที่กำหนด แล้วส่งให้ผู้ใช้ดาวน์โหลด<br>2. เนื้อหาไฟล์ตรงกับขอบเขต คอลัมน์ และการเรียงลำดับที่แสดงในขั้นตอนตรวจสอบตัวอย่าง<br>3. ระบบบันทึกประวัติการส่งออก พร้อมประเภทข้อมูล ขอบเขต และรูปแบบไฟล์<br>4. ไม่มีการเปลี่ยนแปลงข้อมูลนักเรียน |
| **Basic Flow of Events** | 1. ผู้ใช้กรองรายชื่อนักเรียนในรายการทะเบียนให้ได้กลุ่มที่ต้องการ<br>2. ผู้ใช้เลือกคำสั่งส่งออกข้อมูล<br>3. เจ้าหน้าที่ระบุประเภทข้อมูลที่จะส่งออก ขอบเขตของนักเรียนที่จะส่งออก คอลัมน์ที่จะแสดง และรูปแบบไฟล์<br>4. ระบบแสดงตัวอย่างข้อมูลจริงตามที่กำหนดไว้ให้ตรวจสอบก่อนยืนยัน<br>5. ผู้ใช้ยืนยันการส่งออก<br>6. ระบบสร้างไฟล์ตามที่กำหนด ส่งให้ผู้ใช้ดาวน์โหลด บันทึกประวัติ และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow B — พิมพ์บัตรประจำตัวนักเรียน:** ผู้ใช้เลือกพิมพ์บัตรประจำตัวนักเรียนของกลุ่มที่กำหนด ระบบแสดงตัวอย่างบัตรให้ตรวจสอบก่อนสั่งพิมพ์ผ่านระบบพิมพ์เอกสาร<br><br>**Alt Flow C — ส่งข้อมูลไปยังหน่วยงานต้นสังกัด:** ผู้ใช้เลือกส่งข้อมูลนักเรียนไปยังระบบของหน่วยงานต้นสังกัด โดยเลือกได้ระหว่างการเชื่อมต่อโดยตรงกับการส่งออกเป็นไฟล์ตามรูปแบบที่หน่วยงานกำหนด<br><br>**Exception 3a — เงื่อนไขไม่ครบถ้วน:** ระบบแจ้งว่ายังไม่ได้เลือกขอบเขตหรือคอลัมน์ที่จะแสดง และไม่ดำเนินการต่อจนกว่าจะระบุครบ<br><br>**Exception 3b — ไม่มีนักเรียนตรงตามเงื่อนไข:** ระบบแจ้งว่าไม่มีนักเรียนที่จะส่งออกตามเงื่อนไขที่กำหนด |

## UC-REG-07 ส่งออกรายงานและสถิติ

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ส่งออกรายงานและสถิติ |
| **ID** | UC-REG-07 |
| **Scenario** | ผู้อำนวยการขอรายงานสรุปจำนวนนักเรียนแยกตามระดับชั้นสำหรับการประชุมประจำเดือน และฝ่ายทะเบียนต้องจัดทำรายงานนักเรียนลาออกของภาคเรียนปัจจุบันส่งหน่วยงานต้นสังกัด |
| **Trigger Event** | ถึงกำหนดรายงานประจำงวด หรือผู้บริหารหรือหน่วยงานต้นสังกัดร้องขอรายงานสถิตินักเรียน |
| **Brief Description** | แสดงภาพรวมสถิติจำนวนนักเรียนแยกตามระดับชั้นและสถานะ พร้อมสั่งพิมพ์รายงานสรุป และส่งออกรายงานเฉพาะเรื่อง ได้แก่ รายงานนักเรียนลาออกและรายงานนักเรียนใหม่ ตามปีการศึกษาและภาคเรียนที่เลือก |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครู (Primary) · ระบบพิมพ์เอกสาร (Secondary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า<br>เกี่ยวข้องกับ UC-REG-06 ส่งออกรายชื่อนักเรียน — รายงานลาออกและรายงานนักเรียนใหม่ใช้ขั้นตอนส่งออกเดียวกัน<br>เกี่ยวข้องกับ UC-REG-05 จัดการนักเรียนลาออก — วันที่เปลี่ยนสถานะที่บันทึกไว้เป็นฐานของรายงานลาออก |
| **Stakeholders** | ผู้อำนวยการโรงเรียน, ฝ่ายวิชาการ, นายทะเบียน, หน่วยงานต้นสังกัด |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบในบทบาทที่มีสิทธิ์ดูข้อมูลนักเรียน<br>2. ระบบมีข้อมูลนักเรียนในทะเบียน<br>3. กรณีรายงานเฉพาะเรื่อง ต้องมีนักเรียนที่ตรงกับเงื่อนไขปีการศึกษาและภาคเรียนที่เลือกอย่างน้อย 1 คน |
| **Post-Conditions** | 1. ระบบแสดงตารางสถิติจำนวนนักเรียนแยกตามระดับชั้นและสถานะ พร้อมยอดรวม<br>2. ระบบสร้างไฟล์รายงานตามรูปแบบที่เลือก และส่งให้ผู้ใช้ดาวน์โหลดหรือสั่งพิมพ์<br>3. ระบบบันทึกประวัติการออกรายงาน<br>4. ไม่มีการเปลี่ยนแปลงข้อมูลนักเรียน |
| **Basic Flow of Events** | 1. ผู้ใช้เลือกดูรายงานสถิตินักเรียนรายชั้นเรียน<br>2. ระบบคำนวณจากข้อมูลนักเรียนทั้งระบบและแสดงตารางสถิติแยกตามระดับชั้นและสถานะ<br>3. ผู้ใช้เลือกพิมพ์รายงานสรุป<br>4. ระบบแสดงตัวอย่างรายงานให้ตรวจสอบก่อนยืนยัน<br>5. ผู้ใช้ยืนยันการพิมพ์<br>6. ระบบสร้างรายงาน ส่งคำสั่งพิมพ์ผ่านระบบพิมพ์เอกสาร บันทึกประวัติ และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 3a — ส่งออกรายงานลาออกหรือรายงานนักเรียนใหม่:** ผู้ใช้เลือกส่งออกรายงานเฉพาะเรื่องแทนการพิมพ์รายงานสรุป ระบุปีการศึกษาและภาคเรียนที่ต้องการ ระบบคัดกรองนักเรียนตามช่วงเวลานั้นแล้วแสดงตัวอย่างก่อนส่งออกเป็นไฟล์<br><br>**Exception 3a — ไม่พบข้อมูลในช่วงเวลาที่เลือก:** ระบบแจ้งว่าไม่มีนักเรียนที่ตรงกับเงื่อนไขปีการศึกษาและภาคเรียนที่เลือก และให้ผู้ใช้เปลี่ยนช่วงเวลาได้ทันที |

## UC-REG-08 ส่งออก ปพ.1 และ ปพ.2

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ส่งออก ปพ.1 และ ปพ.2 |
| **ID** | UC-REG-08 |
| **Scenario** | หลังพิธีจบการศึกษา ฝ่ายทะเบียนต้องออกใบประกาศนียบัตร (ปพ.2) ให้นักเรียนที่สำเร็จการศึกษาทั้งรุ่น และออกระเบียนแสดงผลการเรียน (ปพ.1) ฉบับภาษาอังกฤษให้นักเรียนบางส่วนที่จะไปศึกษาต่อต่างประเทศ |
| **Trigger Event** | นักเรียนสำเร็จการศึกษาและถึงกำหนดออกเอกสารสำคัญทางการศึกษา หรือนักเรียนหรือศิษย์เก่ายื่นคำร้องขอเอกสาร |
| **Brief Description** | ออกเอกสารสำคัญทางการศึกษา 2 ชนิด คือ ปพ.2 ใบประกาศนียบัตรสำเร็จการศึกษา และ ปพ.1 ระเบียนแสดงผลการเรียน โดยเลือกกลุ่มเป้าหมายตามสถานะและระดับชั้น ปรับรายชื่อทีละคนได้ และตรวจสอบตัวอย่างเอกสารก่อนสั่งพิมพ์ |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) · ระบบพิมพ์เอกสาร (Secondary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — เลือกกลุ่มเป้าหมายจากเงื่อนไขหรือรายชื่อที่เลือก<br>«extend» UC-REG-04 ย้ายห้องเรียน เลื่อนชั้นนักเรียน — นักเรียนต้องผ่านการบันทึกสำเร็จการศึกษาก่อนจึงจะอยู่ในกลุ่มเป้าหมายหลักของ ปพ.2 |
| **Stakeholders** | นักเรียน, ศิษย์เก่า, ผู้ปกครอง, นายทะเบียน, ผู้อำนวยการโรงเรียน, สถาบันการศึกษาปลายทาง |
| **Pre-Conditions** | 1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. มีนักเรียนที่ตรงกับกลุ่มเป้าหมายและระดับชั้นที่เลือกอย่างน้อย 1 คน<br>3. ผลการเรียนของนักเรียนได้รับการอนุมัติจากฝ่ายวิชาการแล้ว และมีผู้ลงนามเอกสารกำหนดไว้ |
| **Post-Conditions** | 1. ระบบสร้างเอกสาร ปพ.1 หรือ ปพ.2 ของนักเรียนแต่ละคนตามรูปแบบและภาษาที่เลือก<br>2. ระบบบันทึกประวัติการออกเอกสาร พร้อมจำนวนฉบับและกลุ่มเป้าหมาย<br>3. การออกเอกสารไม่เปลี่ยนสถานะของนักเรียน การบันทึกสำเร็จการศึกษาเป็นหน้าที่ของ UC-REG-04 |
| **Basic Flow of Events** | 1. ฝ่ายทะเบียนเลือกออกเอกสาร ปพ.2 ใบประกาศนียบัตร<br>2. ฝ่ายทะเบียนระบุกลุ่มเป้าหมายและระดับชั้นของนักเรียนที่จะออกเอกสาร<br>3. ระบบแสดงรายชื่อนักเรียนที่ตรงตามเงื่อนไข พร้อมเตือนหากมีรายใดยังไม่มีสถานะสำเร็จการศึกษา<br>4. ฝ่ายทะเบียนปรับรายชื่อทีละคนได้ตามต้องการ<br>5. ระบบแสดงตัวอย่างเอกสารให้ตรวจสอบก่อนยืนยัน<br>6. ฝ่ายทะเบียนยืนยันและสั่งพิมพ์<br>7. ระบบสร้างเอกสารทั้งชุด บันทึกประวัติพร้อมกลุ่มเป้าหมายและจำนวนฉบับ และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 1a — ออกเอกสารเฉพาะนักเรียนที่เลือก:** ฝ่ายทะเบียนเลือกนักเรียนในรายการทะเบียนก่อน แล้วออกเอกสาร ปพ.2 เฉพาะรายชื่อที่เลือกไว้โดยไม่ต้องระบุระดับชั้นซ้ำ<br><br>**Alt Flow B — ออกเอกสาร ปพ.1 ระเบียนแสดงผลการเรียน:** ฝ่ายทะเบียนเลือกออกเอกสาร ปพ.1 แทน ระบุกลุ่มเป้าหมายและภาษาของเอกสารระหว่างภาษาไทยกับภาษาอังกฤษ ระบบแสดงตัวอย่างเอกสารตามภาษาที่เลือกก่อนยืนยันสร้างเอกสาร<br><br>**Exception 3a — ไม่มีนักเรียนตรงตามเงื่อนไข:** ระบบแจ้งว่าไม่พบนักเรียนที่ตรงกับกลุ่มเป้าหมายและระดับชั้นที่เลือก และไม่ให้ดำเนินการต่อจนกว่าจะปรับเงื่อนไข |

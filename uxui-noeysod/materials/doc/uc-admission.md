# Use Case Description — หมวดที่ 2: งานรับสมัครนักเรียน

หมวดนี้ครอบคลุมงานของเจ้าหน้าที่ทะเบียนที่ดำเนินการกับข้อมูลผู้สมัครหลังจากได้รับใบสมัครเข้าสู่ระบบแล้ว
งานฝั่งผู้สมัครเอง (ยื่นใบสมัคร, ตรวจสอบสถานะ) แยกไว้ที่ [`uc-applicant.md`]((not%20sure)%20uc-applicant.md)

> Actor, Stakeholder และกฎธุรกิจร่วม (`BR-xx`) ดูที่ [`use-case-description-index.md`](./use-case-description-index.md)

## UC-ADM-01 จัดการข้อมูลผู้สมัคร

| หัวข้อ                        | รายละเอียด                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Use Case Name**             | จัดการข้อมูลผู้สมัคร                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **ID**                        | UC-ADM-01                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Scenario**                  | เจ้าหน้าที่ทะเบียนพบว่าผู้สมัครรายหนึ่งกรอกเลขประจำตัวประชาชนผิดตอนสมัคร จึงต้องค้นหาและแก้ไขข้อมูลให้ถูกต้อง และยังพบใบสมัครซ้ำอีกหนึ่งใบที่ผู้ปกครองส่งเข้ามาสองครั้งโดยไม่ได้ตั้งใจซึ่งต้องลบออก                                                                                                                                                                                                                                                                                        |
| **Trigger Event**             | เจ้าหน้าที่ทะเบียนต้องการค้นหา ตรวจสอบ แก้ไข หรือลบข้อมูลผู้สมัครที่มีอยู่ในระบบ                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Brief Description**         | เจ้าหน้าที่ทะเบียนค้นหา เรียกดูรายละเอียด แก้ไข และลบข้อมูลผู้สมัครที่ยื่นเข้ามาในระบบตลอดกระบวนการคัดเลือก                                                                                                                                                                                                                                                                                                                                                                                |
| **Actor(s)**                  | ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary)                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Related Use Cases**         | เกี่ยวข้องกับ UC-APP-01 ยื่นใบสมัครเรียนออนไลน์ — ใบสมัครที่ยื่นเข้ามาอยู่ในความดูแลของ Use Case นี้<br>เป็น Use Case ฐานที่ UC-ADM-02, UC-ADM-03, UC-ADM-04 และ UC-ADM-05 ต้อง «include» ก่อนดำเนินการเสมอ                                                                                                                                                                                                                                                                                |
| **Stakeholders**              | ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, นายทะเบียน                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Pre-Conditions**            | 1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. มีข้อมูลผู้สมัครอยู่ในระบบอย่างน้อย 1 ราย                                                                                                                                                                                                                                                                                                                                                                                       |
| **Post-Conditions**           | 1. ข้อมูลผู้สมัครที่ค้นหาแสดงผลถูกต้องตามเงื่อนไข<br>2. ข้อมูลที่แก้ไขถูกบันทึกพร้อมประวัติผู้แก้ไขและเวลาที่แก้ไข<br>3. ข้อมูลที่ถูกลบจะไม่ปรากฏในระบบอีกต่อไป และไม่สามารถกู้คืนได้                                                                                                                                                                                                                                                                                                      |
| **Basic Flow of Events**      | 1. เจ้าหน้าที่ทะเบียนเข้าสู่รายการผู้สมัคร<br>2. ระบบแสดงรายการผู้สมัครแยกตามขั้นตอนของกระบวนการคัดเลือก<br>3. เจ้าหน้าที่ทะเบียนค้นหาหรือกรองรายการตามชื่อ รหัสผู้สมัคร ระดับชั้น หรือแผนการเรียน<br>4. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครที่ต้องการดูรายละเอียด<br>5. ระบบแสดงประวัติและความคืบหน้าของผู้สมัครรายนั้น<br>6. เจ้าหน้าที่ทะเบียนเลือกแก้ไขข้อมูลและระบุข้อมูลที่ต้องการปรับปรุง<br>7. ระบบตรวจสอบความถูกต้องของข้อมูล บันทึกการเปลี่ยนแปลง พร้อมบันทึกผู้แก้ไขและเวลาที่แก้ไข |
| **Alternate/Exception Flows** | **Alt Flow 6a — ลบข้อมูลผู้สมัคร:** เจ้าหน้าที่ทะเบียนเลือกลบข้อมูลผู้สมัครแทนการแก้ไข ระบบแสดงคำเตือนว่าการลบไม่สามารถกู้คืนได้และให้ยืนยันก่อนดำเนินการ เมื่อยืนยันแล้วระบบลบข้อมูลออกจากระบบและบันทึกประวัติการดำเนินการ<br><br>**Exception 3a — ไม่พบข้อมูลตามเงื่อนไข:** ระบบแจ้งว่าไม่พบผู้สมัครที่ตรงกับเงื่อนไขการค้นหา และแนะนำให้ปรับเงื่อนไขใหม่<br><br>**Exception 7a — ข้อมูลที่จำเป็นไม่ครบถ้วน:** ระบบแจ้งว่าข้อมูลบังคับยังไม่ครบ และไม่บันทึกจนกว่าจะแก้ไขให้ถูกต้อง      |

## UC-ADM-02 พิจารณาเอกสารผู้สมัคร

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | พิจารณาเอกสารผู้สมัคร |
| **ID** | UC-ADM-02 |
| **Scenario** | ก่อนปิดรับสมัคร เจ้าหน้าที่ทะเบียนต้องตรวจเอกสารแนบของผู้สมัครทั้งหมดในขั้นตอนแรก พบว่าผู้สมัครหลายรายยังส่งเอกสารแสดงผลการเรียนไม่ครบ จึงต้องบันทึกผลการตรวจสอบไว้เพื่อติดตามกับผู้ปกครอง |
| **Trigger Event** | เจ้าหน้าที่ทะเบียนเปิดตรวจเอกสารของผู้สมัคร หรือผู้สมัครส่งเอกสารเพิ่มเติมเข้ามาในระบบ |
| **Brief Description** | เจ้าหน้าที่ทะเบียนตรวจสอบความครบถ้วนและความถูกต้องของเอกสารหลักฐานที่ผู้สมัครแนบมา บันทึกผลการพิจารณาเพื่อใช้เป็นเงื่อนไขในการอนุมัติให้เข้าสอบและใช้แจ้งเตือนผู้ปกครอง |
| **Actor(s)** | ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary) |
| **Related Use Cases** | «include» UC-ADM-01 จัดการข้อมูลผู้สมัคร — ต้องเข้าถึงรายการผู้สมัครก่อนดำเนินการ<br>เกี่ยวข้องกับ UC-SET-ADM-01 ตั้งค่าฟอร์มรับสมัครนักเรียน — รายการเอกสารที่ต้องตรวจมาจากการตั้งค่านั้น<br>«extend» UC-ADM-04 ส่งอีเมลถึงผู้สมัคร — ติดตามเอกสารที่ยังขาดกับผู้ปกครอง |
| **Stakeholders** | ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, นายทะเบียน |
| **Pre-Conditions** | 1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. ผู้สมัครที่จะตรวจมีอยู่ในระบบและได้แนบเอกสารไว้แล้ว<br>3. มีการกำหนดรายการเอกสารที่ต้องใช้ไว้ล่วงหน้า |
| **Post-Conditions** | 1. ผลการพิจารณาเอกสารของผู้สมัคร (ครบถ้วนหรือไม่ครบ) ถูกบันทึกไว้<br>2. สถานะเอกสารที่แสดงในรายการผู้สมัครและรายละเอียดผู้สมัครตรงกันทันที<br>3. ผู้สมัครที่เอกสารไม่ครบถูกรวมเป็นกลุ่มเป้าหมายสำหรับการแจ้งเตือน |
| **Basic Flow of Events** | 1. เจ้าหน้าที่ทะเบียนเปิดรายการผู้สมัครในขั้นตอนแรกของกระบวนการคัดเลือก<br>2. ระบบแสดงสถานะความครบถ้วนของเอกสารของผู้สมัครแต่ละราย<br>3. เจ้าหน้าที่ทะเบียนเลือกดูเอกสารที่แนบมาของผู้สมัครรายหนึ่ง<br>4. ระบบแสดงรายการเอกสารที่ผู้สมัครแนบไว้พร้อมสถานะการอัปโหลดของแต่ละรายการ<br>5. เจ้าหน้าที่ทะเบียนตรวจสอบเอกสารแต่ละรายการ<br>6. เจ้าหน้าที่ทะเบียนบันทึกผลการพิจารณาว่าเอกสารครบถ้วนหรือไม่ พร้อมระบุรายการที่ขาด<br>7. ระบบบันทึกผล และปรับสถานะเอกสารที่แสดงในรายการผู้สมัครและรายละเอียดผู้สมัคร |
| **Alternate/Exception Flows** | **Alt Flow 6a — พิจารณาเอกสารหลายรายพร้อมกัน:** เจ้าหน้าที่ทะเบียนเลือกผู้สมัครหลายรายพร้อมกันแล้วบันทึกผลการพิจารณาให้ทั้งกลุ่ม<br><br>**Alt Flow 7a — แจ้งผู้ปกครองให้ส่งเอกสารเพิ่ม:** หลังบันทึกผลว่าเอกสารไม่ครบ เจ้าหน้าที่ทะเบียนเลือกกลุ่มผู้สมัครนั้นแล้วส่งอีเมลแจ้งเตือนเอกสารไม่ครบให้ผู้ปกครองทราบ<br><br>**Exception 3a — ไม่พบข้อมูลผู้สมัคร:** ระบบแจ้งว่าไม่พบผู้สมัครรายนั้น และไม่แสดงรายการเอกสาร |

## UC-ADM-03 จัดการสถานะผู้สมัคร

| หัวข้อ                        | รายละเอียด                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**             | จัดการสถานะผู้สมัคร                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **ID**                        | UC-ADM-03                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Scenario**                  | หลังปิดการสอบคัดเลือก คณะกรรมการประกาศผลแล้ว เจ้าหน้าที่ทะเบียนต้องบันทึกคะแนนสอบของผู้สมัคร แล้วเปลี่ยนสถานะผู้สมัครหลายรายพร้อมกันเป็น "สอบผ่าน" และอีกกลุ่มเป็น "สำรอง"                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Trigger Event**             | มีเหตุการณ์ที่ทำให้ต้องปรับสถานะผู้สมัคร เช่น คณะกรรมการประกาศผลสอบ หรือได้รับแจ้งการชำระเงินจากฝ่ายการเงิน                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Brief Description**         | เจ้าหน้าที่ทะเบียนปรับสถานะผู้สมัครให้สอดคล้องกับความคืบหน้าของกระบวนการคัดเลือก ทั้งรายบุคคลและเป็นกลุ่ม พร้อมบันทึกคะแนนสอบ โดยมีการยืนยันก่อนดำเนินการทุกครั้งและสามารถย้อนกลับการดำเนินการได้                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Actor(s)**                  | ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Related Use Cases**         | «include» UC-ADM-01 จัดการข้อมูลผู้สมัคร — ต้องเข้าถึงรายการผู้สมัครก่อนดำเนินการ<br>«extend» UC-APP-02 ตรวจสอบสถานะและยืนยันสิทธิ์การเข้าศึกษา — ผู้สมัครสามารถทำให้สถานะเปลี่ยนได้ด้วยตนเองในลักษณะเดียวกัน<br>«extend» UC-ADM-04 ส่งอีเมลถึงผู้สมัคร — แจ้งผลการเปลี่ยนสถานะให้ผู้ปกครองทราบ                                                                                                                                                                                                                                                                                                                               |
| **Stakeholders**              | ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, ฝ่ายวิชาการ, ฝ่ายการเงิน, ผู้อำนวยการโรงเรียน                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Pre-Conditions**            | 1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. มีผู้สมัครที่จะเปลี่ยนสถานะอยู่ในระบบ<br>3. คณะกรรมการอนุมัติผลการคัดเลือกแล้วในกรณีประกาศผลสอบ                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Post-Conditions**           | 1. ผู้สมัครมีสถานะใหม่ตามที่กำหนด และถูกจัดกลุ่มตามขั้นตอนที่ตรงกับสถานะนั้นโดยอัตโนมัติ<br>2. เมื่อสถานะเปลี่ยนเป็น "กำลังศึกษา หรือ มอบตัวเสร็จสิ้น" ระบบออกรหัสนักเรียนให้อัตโนมัติตาม BR-02 และผู้สมัครกลายเป็นนักเรียนในทะเบียน<br>3. คะแนนสอบที่บันทึกปรากฏในรายละเอียดของผู้สมัครทันที<br>4. เจ้าหน้าที่ทะเบียนสามารถย้อนกลับการเปลี่ยนสถานะได้ทันทีหลังดำเนินการ ทั้งรายบุคคลและรายกลุ่ม                                                                                                                                                                                                                              |
| **Basic Flow of Events**      | 1. เจ้าหน้าที่ทะเบียนเลือกกลุ่มผู้สมัครตามขั้นตอนของกระบวนการคัดเลือกที่ต้องการดำเนินการ<br>2. ระบบแสดงรายการผู้สมัครในขั้นตอนนั้น<br>3. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครหนึ่งรายหรือหลายรายที่ต้องการปรับสถานะ<br>4. เจ้าหน้าที่ทะเบียนระบุสถานะใหม่ที่ต้องการเปลี่ยน<br>5. ระบบแสดงรายละเอียดการเปลี่ยนแปลงให้ตรวจสอบก่อนยืนยัน รวมถึงแจ้งหากผู้สมัครจะถูกย้ายไปยังขั้นตอนอื่น<br>6. เจ้าหน้าที่ทะเบียนยืนยันการเปลี่ยนสถานะ<br>7. ระบบบันทึกสถานะใหม่ของผู้สมัครทุกรายที่เลือก และแจ้งผลการดำเนินการพร้อมทางเลือกให้ย้อนกลับ                                                                                                |
| **Alternate/Exception Flows** | **Alt Flow 7a — ย้อนกลับการเปลี่ยนสถานะ:** เจ้าหน้าที่ทะเบียนเลือกย้อนกลับภายในเวลาที่กำหนดหลังดำเนินการ ระบบคืนค่าสถานะเดิมของผู้สมัครทุกรายในชุดนั้น<br><br>**Alt Flow B — บันทึกคะแนนสอบ:** เจ้าหน้าที่ทะเบียนเลือกกรอกหรือแก้ไขคะแนนสอบของผู้สมัคร ระบุคะแนนดิบและคะแนนเฉลี่ยสะสม ระบบบันทึกคะแนนโดยไม่เปลี่ยนสถานะของผู้สมัคร ซึ่งเจ้าหน้าที่ทะเบียนต้องเปลี่ยนสถานะแยกต่างหากตามผลคะแนนนั้น<br><br>**Exception 6a — ยกเลิกก่อนยืนยัน:** เจ้าหน้าที่ทะเบียนยกเลิกการดำเนินการก่อนยืนยัน ระบบไม่เปลี่ยนแปลงสถานะใดๆ<br><br>**Exception B1a — กรอกคะแนนไม่ครบ:** ระบบแจ้งว่ายังกรอกคะแนนไม่ครบ และไม่บันทึกจนกว่าจะกรอกครบ |

| **Alternate/Exception Flows** | **Alt Flow 1a — ส่งอีเมลรายบุคคล:** เจ้าหน้าที่ทะเบียนเลือกส่งอีเมลแจ้งผลให้ผู้สมัครรายเดียวจากรายละเอียดผู้สมัคร ระบบเปิดหน้าแต่งอีเมลโดยมีผู้รับเพียงรายเดียว<br><br>**Alt Flow 4a — เขียนเนื้อหาอิสระ:** เจ้าหน้าที่ทะเบียนเลือกเขียนเนื้อหาเองแทนการใช้เนื้อหาสำเร็จรูป ระบบเปิดให้ระบุหัวข้อและเนื้อหาใหม่ทั้งหมด<br><br>**Exception 2a — ไม่มีรายชื่อผู้รับ:** ระบบแจ้งว่าไม่มีผู้รับปลายทาง และให้กลับไปเลือกผู้สมัครที่ต้องการแจ้งเตือนก่อน<br><br>**Exception 6a — ข้อมูลที่จำเป็นไม่ครบ:** ระบบแจ้งว่ายังไม่ได้ระบุหัวข้อหรือเนื้อหา และไม่ส่งจนกว่าจะกรอกครบ                                                                                                     |

## UC-ADM-05 ส่งออกใบสมัคร

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ส่งออกใบสมัคร |
| **ID** | UC-ADM-05 |
| **Scenario** | คณะกรรมการรับนักเรียนขอชุดใบสมัครฉบับพิมพ์ของผู้สมัครในขั้นตอนแรกเพื่อใช้ประกอบการประชุมพิจารณา และฝ่ายการเงินขอใบเสร็จค่าสมัครสอบของผู้สมัครที่ชำระเงินแล้วไปเก็บเป็นหลักฐาน |

| **Brief Description** | เจ้าหน้าที่ทะเบียนสร้างและส่งออกเอกสารของผู้สมัคร ได้แก่ ใบสมัครและแสดงความจำนง ใบแจ้งยอดและหลักฐานการจ่ายเงินค่าสอบ และใบมอบตัวและข้อมูลห้องเรียน โดยมีขั้นตอนตรวจสอบตัวอย่างก่อนดำเนินการจริง |
| **Actor(s)** | ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary) · ระบบพิมพ์เอกสาร (Secondary) |

# Use Case Description — หมวดที่ 0: งานฝั่งผู้สมัครและผู้ปกครอง

Use Case ในหมวดนี้มี **ผู้สมัคร หรือ ผู้ปกครอง** เป็น Primary Actor ซึ่งเป็นบุคคลภายนอกสถานศึกษา
ต่างจากหมวดอื่นที่ Primary Actor เป็นเจ้าหน้าที่ของโรงเรียน

> Actor, Stakeholder และกฎธุรกิจร่วม (`BR-xx`) ดูที่ [`use-case-description-index.md`](./use-case-description-index.md)

---

## UC-APP-01 ยื่นใบสมัครเรียนออนไลน์

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ยื่นใบสมัครเรียนออนไลน์ |
| **ID** | UC-APP-01 |
| **Scenario** | ผู้ปกครองต้องการสมัครให้บุตรหลานเข้าเรียนชั้น ม.1 แผนวิทยาศาสตร์-คณิตศาสตร์ จึงเข้าระบบรับสมัครออนไลน์ของโรงเรียนเพื่อระบุข้อมูลประวัติและแนบเอกสารหลักฐานด้วยตนเอง |
| **Trigger Event** | ผู้สมัครหรือผู้ปกครองเข้าสู่ระบบรับสมัครออนไลน์ในช่วงเวลาที่เปิดรับสมัคร |
| **Brief Description** | ผู้สมัครระบุข้อมูลประวัติและแนบเอกสารหลักฐานประกอบการสมัครผ่านระบบออนไลน์ จนได้รับรหัสใบสมัครสำหรับใช้ติดตามสถานะในขั้นตอนต่อไป |
| **Actor(s)** | ผู้สมัคร หรือ ผู้ปกครอง (Primary) |
| **Related Use Cases** | «extend» UC-APP-02 ตรวจสอบสถานะและยืนยันสิทธิ์การเข้าศึกษา — ใช้รหัสใบสมัครที่ได้รับติดตามผลในขั้นถัดไป<br>เกี่ยวข้องกับ UC-ADM-01 จัดการข้อมูลผู้สมัคร — ใบสมัครที่ยื่นเข้ามาอยู่ในความดูแลของเจ้าหน้าที่ทะเบียน<br>เกี่ยวข้องกับ UC-SET-ADM-03 ตั้งค่าและจัดการกำหนดการรับสมัคร — ช่วงเวลาเปิดรับสมัครเป็นเงื่อนไขนำเข้าของ Use Case นี้<br>เกี่ยวข้องกับ UC-SET-ADM-01 ตั้งค่าฟอร์มรับสมัครนักเรียน — ข้อมูลที่ต้องระบุเป็นไปตามที่ตั้งค่าไว้ |
| **Stakeholders** | นักเรียนผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, เจ้าหน้าที่ทะเบียน, ฝ่ายวิชาการ |
| **Pre-Conditions** | 1. ระบบอยู่ในช่วงเวลาเปิดรับสมัครตามกำหนดการที่ประกาศไว้<br>2. มีแผนการเรียนที่เปิดรับสมัครอย่างน้อย 1 แผน<br>3. ผู้สมัครมีเอกสารหลักฐานประกอบการสมัครในรูปแบบไฟล์พร้อมสำหรับแนบเข้าระบบ |
| **Post-Conditions** | 1. ใบสมัครถูกบันทึกเข้าสู่ระบบ พร้อมรหัสใบสมัครที่ระบบออกให้อัตโนมัติตาม BR-01<br>2. สถานะของผู้สมัครถูกตั้งต้นเป็น "ยังไม่ได้ชำระเงินค่าสอบ"<br>3. ใบสมัครปรากฏในรายการของเจ้าหน้าที่ทะเบียนเพื่อรอการพิจารณาเอกสาร<br>4. ผู้สมัครสามารถใช้รหัสใบสมัครติดตามสถานะได้ทันที |
| **Basic Flow of Events** | 1. ผู้สมัครเข้าสู่ระบบรับสมัครเรียนออนไลน์<br>2. ระบบแสดงแบบฟอร์มการรับสมัครแบ่งตามขั้นตอน พร้อมแสดงความคืบหน้าของแต่ละขั้น<br>3. ผู้สมัครเลือกระดับชั้นและแผนการเรียนที่ต้องการสมัคร โดยระบุได้ถึง 2 อันดับ<br>4. ผู้สมัครระบุข้อมูลส่วนบุคคล ข้อมูลที่อยู่ ข้อมูลครอบครัวและผู้ปกครอง ประวัติการศึกษาเดิม และข้อมูลสุขภาพ<br>5. ผู้สมัครแนบเอกสารหลักฐานประกอบการสมัครตามรายการที่สถานศึกษากำหนด<br>6. ผู้สมัครยืนยันการส่งใบสมัคร<br>7. ระบบตรวจสอบความครบถ้วนของข้อมูลและเอกสาร บันทึกใบสมัคร ออกรหัสใบสมัคร และกำหนดสถานะตั้งต้นเป็น "ยังไม่ได้ชำระเงินค่าสอบ"<br>8. ระบบแจ้งผลการสมัครสำเร็จพร้อมรหัสใบสมัคร ข้อมูลสรุปการสมัคร และหลักฐานยืนยันการยื่นใบสมัคร |
| **Alternate/Exception Flows** | **Alt Flow 4a — ดึงข้อมูลจากบัตรประจำตัวประชาชน:** ผู้สมัครเลือกให้ระบบอ่านข้อมูลจากภาพบัตรประจำตัวประชาชน ระบบดึงข้อมูลประวัติส่วนบุคคลมาระบุให้อัตโนมัติ เพื่อให้ผู้สมัครตรวจสอบและแก้ไขก่อนดำเนินการต่อ<br><br>**Alt Flow 4b — ใช้ที่อยู่ร่วมกัน:** ผู้สมัครเลือกใช้ที่อยู่เดียวกับที่อยู่ของนักเรียนหรือของบิดา ระบบคัดลอกข้อมูลที่อยู่ให้อัตโนมัติ เพื่อลดการระบุข้อมูลซ้ำ<br><br>**Alt Flow 6a — ย้อนกลับไปแก้ไขข้อมูล:** ผู้สมัครย้อนกลับไปยังขั้นตอนก่อนหน้าเพื่อแก้ไขข้อมูล โดยข้อมูลที่ระบุไว้แล้วทั้งหมดยังคงอยู่<br><br>**Exception 7a — ข้อมูลบังคับไม่ครบถ้วนหรือไม่ถูกต้อง:** ระบบแจ้งรายการข้อมูลหรือเอกสารที่ยังไม่ครบ หรือที่อยู่ในรูปแบบไม่ถูกต้อง เช่น เลขประจำตัวประชาชนไม่ครบ 13 หลัก และไม่อนุญาตให้ดำเนินการขั้นถัดไปจนกว่าผู้สมัครจะแก้ไขให้ถูกต้อง<br><br>**Exception 1a — อยู่นอกช่วงเวลารับสมัคร:** ระบบปฏิเสธการเข้าถึงแบบฟอร์มการรับสมัคร และแสดงกำหนดการรับสมัครของแต่ละแผนการเรียนให้ผู้สมัครทราบ |

## UC-APP-02 ตรวจสอบสถานะและยืนยันสิทธิ์การเข้าศึกษา

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ตรวจสอบสถานะและยืนยันสิทธิ์การเข้าศึกษา |
| **ID** | UC-APP-02 |
| **Scenario** | หลังยื่นใบสมัครแล้ว ผู้ปกครองต้องการทราบว่าต้องชำระค่าสมัครสอบเมื่อใด สอบห้องไหน และเมื่อประกาศผลแล้วบุตรหลานสอบผ่านหรือไม่ จึงเข้าระบบตรวจสอบสถานะด้วยรหัสใบสมัคร และยืนยันสิทธิ์การเข้าศึกษาออนไลน์หลังทราบผลว่าสอบผ่าน |
| **Trigger Event** | ผู้สมัครหรือผู้ปกครองต้องการติดตามความคืบหน้าของการสมัคร ชำระค่าสมัครสอบ หรือยืนยันสิทธิ์การเข้าศึกษา |
| **Brief Description** | ผู้สมัครติดตามความคืบหน้าของการคัดเลือกด้วยตนเอง ชำระค่าสมัครสอบ ตรวจสอบสถานที่สอบและผลการสอบ และยืนยันสิทธิ์การเข้าศึกษาผ่านระบบออนไลน์ |
| **Actor(s)** | ผู้สมัคร หรือ ผู้ปกครอง (Primary) · ระบบชำระเงิน (Secondary) |
| **Related Use Cases** | «extend» UC-APP-01 ยื่นใบสมัครเรียนออนไลน์ — ใช้รหัสใบสมัครที่ได้รับจาก Use Case นั้น<br>«extend» UC-ADM-03 จัดการสถานะผู้สมัคร — การดำเนินการของผู้สมัครทำให้สถานะเปลี่ยนแบบเดียวกับที่เจ้าหน้าที่ดำเนินการ<br>เกี่ยวข้องกับ UC-SET-ADM-02 ตั้งค่าห้องสอบผู้สมัคร — ข้อมูลสถานที่สอบและเลขที่นั่งที่แสดงมาจากการจัดห้องสอบ |
| **Stakeholders** | นักเรียนผู้สมัคร, ผู้ปกครอง, เจ้าหน้าที่ทะเบียน, ฝ่ายการเงิน, คณะกรรมการรับนักเรียน |
| **Pre-Conditions** | 1. ผู้สมัครได้ยื่นใบสมัครเข้าสู่ระบบเรียบร้อยแล้ว และมีรหัสใบสมัครหรือเลขประจำตัวประชาชนสำหรับค้นหา<br>2. การยืนยันสิทธิ์ทำได้เฉพาะเมื่อสถานะของผู้สมัครถึงขั้นตอนนั้นแล้ว |
| **Post-Conditions** | 1. ผู้สมัครทราบสถานะปัจจุบันและขั้นตอนถัดไปที่ต้องดำเนินการ<br>2. เมื่อชำระค่าสมัครสอบสำเร็จ สถานะเปลี่ยนเป็น "ชำระเงินค่าสอบแล้ว" และระบบบันทึกการชำระเงิน<br>3. เมื่อยืนยันสิทธิ์การเข้าศึกษาสำเร็จ สถานะเปลี่ยนเป็น "กำลังศึกษา หรือ มอบตัวเสร็จสิ้น" ระบบออกรหัสนักเรียนตาม BR-02 และจัดห้องเรียนให้<br>4. ข้อมูลที่ผู้สมัครดำเนินการปรากฏในรายการของเจ้าหน้าที่ทะเบียนทันที |
| **Basic Flow of Events** | 1. ผู้สมัครเข้าสู่ระบบตรวจสอบสถานะผู้สมัคร<br>2. ผู้สมัครระบุเลขประจำตัวประชาชนหรือรหัสใบสมัครเพื่อค้นหา<br>3. ระบบแสดงความคืบหน้าของกระบวนการคัดเลือกและสถานะปัจจุบันของผู้สมัคร พร้อมขั้นตอนที่ต้องดำเนินการต่อตามสถานะนั้น<br>4. ผู้สมัครที่ยังไม่ได้ชำระค่าสมัครสอบ ดำเนินการชำระเงินผ่านช่องทางที่ระบบกำหนด<br>5. ระบบบันทึกการชำระเงิน ปรับสถานะเป็น "ชำระเงินค่าสอบแล้ว" และแจ้งผลพร้อมแสดงสถานที่สอบ เลขที่นั่งสอบ และกำหนดการสอบ<br>6. เมื่อถึงกำหนดประกาศผล ผู้สมัครตรวจสอบผลการสอบและคะแนนที่ได้รับ<br>7. ผู้สมัครที่สอบผ่านยืนยันสิทธิ์การเข้าศึกษาผ่านระบบ<br>8. ระบบบันทึกการยืนยันสิทธิ์ ปรับสถานะเป็น "กำลังศึกษา หรือ มอบตัวเสร็จสิ้น" ออกรหัสนักเรียน จัดห้องเรียน และแจ้งผลพร้อมหลักฐานการมอบตัว |
| **Alternate/Exception Flows** | **Alt Flow 6a — ผลการคัดเลือกเป็นตัวสำรองหรือไม่ผ่าน:** ระบบแสดงผลการคัดเลือกพร้อมลำดับสำรองในกรณีที่เป็นตัวสำรอง และไม่เปิดให้ยืนยันสิทธิ์จนกว่าสถานะจะเปลี่ยนเป็นสอบผ่าน<br><br>**Alt Flow 8a — ขอหลักฐานฉบับพิมพ์:** ผู้สมัครขอเอกสารหลักฐานการชำระเงินหรือหลักฐานการมอบตัว ระบบสร้างเอกสารให้ผู้สมัครเก็บไว้เป็นหลักฐาน<br><br>**Exception 2a — ไม่พบข้อมูลการสมัคร:** ระบบแจ้งว่าไม่พบข้อมูลตามที่ค้นหา พร้อมแนะนำให้ตรวจสอบความถูกต้องของข้อมูลที่ระบุ<br><br>**Exception 5a — การชำระเงินไม่สำเร็จ:** ระบบแจ้งว่าการชำระเงินไม่สำเร็จ คงสถานะเดิมไว้ และเปิดให้ผู้สมัครดำเนินการชำระเงินใหม่<br><br>**Exception 7a — พ้นกำหนดเวลายืนยันสิทธิ์:** หากพ้นกำหนดวันรายงานตัวและมอบตัวตามปฏิทินการรับสมัครแล้ว ระบบไม่เปิดให้ยืนยันสิทธิ์ และแจ้งให้ผู้สมัครติดต่อเจ้าหน้าที่ทะเบียนโดยตรง |

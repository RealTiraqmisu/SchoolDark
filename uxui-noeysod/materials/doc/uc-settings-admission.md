# Use Case Description — หมวดที่ 3: การตั้งค่างานรับสมัครนักเรียน

หมวดนี้ครอบคลุมการตั้งค่าที่รองรับกระบวนการรับสมัครนักเรียน ได้แก่ ฟอร์มรับสมัคร ห้องสอบ
กำหนดการรับสมัคร และข้อมูลอาคารและห้อง

> Actor, Stakeholder และกฎธุรกิจร่วม (`BR-xx`) ดูที่ [`use-case-description-index.md`](./use-case-description-index.md)

---

## UC-SET-ADM-01 ตั้งค่าฟอร์มรับสมัครนักเรียน

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ตั้งค่าฟอร์มรับสมัครนักเรียน |
| **ID** | UC-SET-ADM-01 |
| **Scenario** | ก่อนเปิดรับสมัครปีการศึกษาใหม่ คณะกรรมการรับนักเรียนมีมติว่าไม่ต้องบังคับให้ผู้สมัครระบุข้อมูลบิดาและมารดาแล้ว เพราะมีผู้สมัครจำนวนหนึ่งที่อยู่ในความดูแลของญาติ ฝ่ายทะเบียนจึงต้องปรับแบบฟอร์มรับสมัครออนไลน์ให้ช่องเหล่านั้นไม่เป็นช่องบังคับ |
| **Trigger Event** | ก่อนเปิดรับสมัครแต่ละปีการศึกษา หรือเมื่อมีมติเปลี่ยนแปลงข้อมูลที่ต้องเก็บจากผู้สมัคร |
| **Brief Description** | กำหนดว่าข้อมูลใดในแบบฟอร์มรับสมัครออนไลน์เป็นข้อมูลที่ผู้สมัครจำเป็นต้องระบุ โดยแบ่งเป็นหมวดข้อมูลตั้งแต่ประวัติส่วนตัวจนถึงหลักฐานการสมัคร |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | เกี่ยวข้องกับ UC-APP-01 ยื่นใบสมัครเรียนออนไลน์ — แบบฟอร์มสมัครเรียนออนไลน์ใช้การตั้งค่านี้ในการตรวจความครบถ้วน<br>เกี่ยวข้องกับ UC-ADM-02 พิจารณาเอกสารผู้สมัคร — รายการในหมวดหลักฐานการสมัครคือรายการเอกสารที่ต้องตรวจ<br>คล้ายกับ UC-SET-REG-01 ตั้งค่าฟอร์มนักเรียน — ใช้โครงหมวดข้อมูลชุดเดียวกัน |
| **Stakeholders** | ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, นายทะเบียน, ฝ่ายวิชาการ |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. ระบบมีโครงข้อมูลตั้งต้นของแบบฟอร์มรับสมัครครบทุกหมวด<br>3. ควรตั้งค่าให้เสร็จก่อนเปิดรับสมัคร เพื่อไม่ให้ผู้สมัครที่ยื่นใบสมัครไปแล้วมีข้อมูลไม่ครบตามเกณฑ์ใหม่ |
| **Post-Conditions** | 1. ค่าความจำเป็นของแต่ละข้อมูลถูกบันทึกลงระบบ<br>2. แบบฟอร์มสมัครเรียนออนไลน์แสดงเครื่องหมายบังคับและตรวจความครบถ้วนตามค่าที่ตั้งไว้ใหม่<br>3. หากผู้ใช้เลือกคืนค่าเดิม การเปลี่ยนแปลงที่ยังไม่ได้บันทึกจะถูกยกเลิกทั้งหมด |
| **Basic Flow of Events** | 1. ผู้ใช้เปิดหน้าตั้งค่าฟอร์มรับสมัคร<br>2. ระบบแสดงหมวดข้อมูลทั้งหมด ตั้งแต่ประวัติส่วนตัว ที่อยู่ ข้อมูลบิดามารดาและผู้ปกครอง ข้อมูลการศึกษา ข้อมูลสุขภาพ ไปจนถึงหลักฐานการสมัคร<br>3. ผู้ใช้เลือกหมวดข้อมูลที่ต้องการปรับ<br>4. ระบบแสดงรายการข้อมูลของหมวดนั้นพร้อมสถานะความจำเป็นปัจจุบัน<br>5. ผู้ใช้กำหนดว่าข้อมูลใดจำเป็นต้องระบุหรือไม่จำเป็น<br>6. ผู้ใช้ยืนยันการบันทึกการตั้งค่า<br>7. ระบบบันทึกค่าทั้งหมดลงระบบและแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 6a — คืนค่าเดิม:** ผู้ใช้เลือกคืนค่าเดิมแทนการบันทึก ระบบทิ้งการเปลี่ยนแปลงที่ยังไม่ได้บันทึกและโหลดค่าที่บันทึกไว้ล่าสุดกลับมาแสดง<br><br>**Exception 6a — บันทึกไม่สำเร็จ:** ระบบแจ้งข้อผิดพลาดและคงค่าที่ผู้ใช้ปรับไว้บนหน้าจอ เพื่อให้บันทึกซ้ำได้โดยไม่ต้องตั้งค่าใหม่ |

## UC-SET-ADM-02 ตั้งค่าห้องสอบผู้สมัคร

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ตั้งค่าห้องสอบผู้สมัคร |
| **ID** | UC-SET-ADM-02 |
| **Scenario** | มีผู้สมัครแผนวิทยาศาสตร์-คณิตศาสตร์จำนวนมาก ฝ่ายทะเบียนต้องจัดห้องสอบคัดเลือกให้เพียงพอ โดยเลือกใช้ห้องเรียนหลายห้องแทนการใช้ห้องประชุมใหญ่ห้องเดียว เพื่อให้คุมสอบได้ทั่วถึง |
| **Trigger Event** | ใกล้ถึงวันสอบคัดเลือกตามกำหนดการรับสมัคร และทราบจำนวนผู้สมัครที่ต้องเข้าสอบในแต่ละแผนการเรียนแล้ว |
| **Brief Description** | สร้างและจัดการห้องสอบคัดเลือก โดยผูกห้องสอบกับแผนการเรียน เลือกห้องเรียนที่จะใช้สอบ กำหนดจำนวนที่นั่ง และติดตามจำนวนผู้สอบที่จัดสรรแล้วในแต่ละห้อง |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | เกี่ยวข้องกับ UC-SET-ADM-04 ตั้งค่าข้อมูลอาคารและห้อง — รายการห้องเรียนและความจุมาจากข้อมูลหลักนั้น<br>เกี่ยวข้องกับ UC-SET-ADM-03 ตั้งค่าและจัดการกำหนดการรับสมัคร — ห้องสอบผูกกับแผนการเรียนที่มีกำหนดการสอบกำกับไว้<br>เกี่ยวข้องกับ UC-APP-02 ตรวจสอบสถานะและยืนยันสิทธิ์การเข้าศึกษา — ผู้สมัครที่ชำระเงินแล้วจะถูกจัดสรรเข้าห้องสอบและได้เลขที่นั่ง |
| **Stakeholders** | ผู้สมัคร, ผู้ปกครอง, คณะกรรมการคุมสอบ, ฝ่ายอาคารสถานที่, ฝ่ายวิชาการ |
| **Pre-Conditions** | 1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. มีแผนการเรียนที่เปิดรับสมัครอยู่ในระบบอย่างน้อย 1 แผน<br>3. มีข้อมูลห้องเรียนพร้อมความจุในระบบอย่างน้อย 1 ห้อง |
| **Post-Conditions** | 1. ห้องสอบถูกบันทึกลงระบบ พร้อมแผนการเรียนที่ผูกไว้ ห้องเรียนที่ใช้ และจำนวนที่นั่ง<br>2. จำนวนที่นั่งสอบรวมของแต่ละแผนการเรียนเพียงพอกับจำนวนผู้สมัครที่ต้องเข้าสอบ<br>3. ระบบนำห้องสอบไปใช้จัดสรรผู้สมัครและออกเลขที่นั่งสอบ ซึ่งผู้สมัครตรวจสอบได้จากการตรวจสอบสถานะ<br>4. เมื่อลบห้องสอบ ผู้สมัครที่เคยถูกจัดสรรไว้ในห้องนั้นจะไม่มีเลขห้องสอบชั่วคราวจนกว่าจะจัดสรรใหม่ |
| **Basic Flow of Events** | 1. ฝ่ายทะเบียนเปิดหน้าตั้งค่าห้องสอบ<br>2. ระบบแสดงรายการห้องสอบที่มีอยู่ พร้อมแผนการเรียนที่ผูกไว้และจำนวนผู้สอบที่จัดสรรแล้ว<br>3. ฝ่ายทะเบียนเลือกเพิ่มห้องสอบใหม่<br>4. ฝ่ายทะเบียนเลือกแผนการเรียนที่จะสอบ<br>5. ระบบแสดงจำนวนผู้สมัครทั้งหมดในแผนนั้นและแนะนำจำนวนห้องเรียนที่ควรใช้<br>6. ฝ่ายทะเบียนเลือกห้องเรียนที่จะใช้สอบและตั้งชื่อห้องสอบ<br>7. ฝ่ายทะเบียนยืนยันการบันทึก<br>8. ระบบสร้างห้องสอบตามห้องเรียนที่เลือก กำหนดจำนวนที่นั่งตามความจุของแต่ละห้อง และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 6a — ใช้คำแนะนำแผนจัดห้องสอบ:** ระบบเสนอแผนจัดห้องสอบสำเร็จรูปตามจำนวนผู้สมัคร ฝ่ายทะเบียนเลือกแผนที่ต้องการแล้วระบบเลือกห้องเรียนตามแผนนั้นให้อัตโนมัติ<br><br>**Alt Flow 3a — แก้ไขหรือลบห้องสอบเดิม:** ฝ่ายทะเบียนเลือกแก้ไขหรือลบห้องสอบที่มีอยู่ กรณีลบ ระบบแสดงคำเตือนว่าผู้สมัครที่จัดสรรไว้ในห้องนั้นจะไม่มีเลขห้องสอบชั่วคราวก่อนให้ยืนยัน<br><br>**Exception 7a — ยังไม่ได้เลือกห้องเรียนหรือยังไม่ได้ตั้งชื่อห้องสอบ:** ระบบแจ้งว่าต้องเลือกห้องเรียนอย่างน้อย 1 ห้องและระบุชื่อห้องสอบก่อนจึงจะบันทึกได้<br><br>**Exception 8a — ที่นั่งไม่พอกับจำนวนผู้สมัคร:** ระบบแจ้งเตือนว่าที่นั่งรวมของแผนการเรียนนี้ยังน้อยกว่าจำนวนผู้สมัครที่ต้องเข้าสอบ พร้อมระบุจำนวนที่ขาด |

## UC-SET-ADM-03 ตั้งค่าและจัดการกำหนดการรับสมัคร

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ตั้งค่าและจัดการกำหนดการรับสมัคร |
| **ID** | UC-SET-ADM-03 |
| **Scenario** | คณะกรรมการรับนักเรียนอนุมัติปฏิทินการรับสมัครปีการศึกษาใหม่แล้ว โดยแผนห้องเรียนพิเศษเปิดรับก่อนแผนทั่วไปหนึ่งสัปดาห์ ฝ่ายทะเบียนต้องบันทึกกำหนดการของแต่ละแผนการเรียนเข้าระบบ เพื่อให้การรับสมัครออนไลน์เปิดปิดตามวันที่จริง และผู้สมัครเห็นกำหนดการที่ถูกต้อง |
| **Trigger Event** | คณะกรรมการรับนักเรียนอนุมัติปฏิทินการรับสมัคร หรือมีการเลื่อนวันสอบ วันประกาศผล หรือวันมอบตัว |
| **Brief Description** | กำหนดและปรับปรุงปฏิทินการรับสมัครของแต่ละแผนการเรียน ครอบคลุมช่วงเวลาสำคัญตั้งแต่วันเปิดและปิดรับสมัครออนไลน์ วันสอบคัดเลือก วันประกาศผล วันรายงานตัว จนถึงวันมอบตัว เพื่อให้ระบบและผู้สมัครอ้างอิงกำหนดการชุดเดียวกัน |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | เกี่ยวข้องกับ UC-APP-01 ยื่นใบสมัครเรียนออนไลน์ — ระบบเปิดให้ยื่นใบสมัครเฉพาะในช่วงวันเปิดถึงวันปิดรับสมัคร<br>เกี่ยวข้องกับ UC-SET-ADM-02 ตั้งค่าห้องสอบผู้สมัคร — ห้องสอบต้องจัดให้เสร็จก่อนวันสอบคัดเลือกที่กำหนดไว้<br>เกี่ยวข้องกับ UC-ADM-03 จัดการสถานะผู้สมัคร — วันประกาศผล วันรายงานตัว และวันมอบตัว เป็นกรอบเวลาของการเปลี่ยนสถานะแต่ละขั้นตอน |
| **Stakeholders** | ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. มีแผนการเรียนที่จะเปิดรับสมัครอยู่ในระบบแล้ว<br>3. ปฏิทินการรับสมัครได้รับการอนุมัติจากคณะกรรมการรับนักเรียนแล้ว |
| **Post-Conditions** | 1. กำหนดการทุกช่วงถูกบันทึกไว้กับแผนการเรียนที่เกี่ยวข้อง<br>2. ระบบรับสมัครออนไลน์เปิดรับใบสมัครเฉพาะในช่วงวันเปิดถึงวันปิดรับสมัครของแผนนั้น<br>3. ระบบตรวจสอบสถานะผู้สมัครแสดงกำหนดการสอบ กำหนดการประกาศผล และกำหนดการมอบตัวตามค่าที่ตั้งไว้<br>4. กำหนดการที่แสดงต่อผู้สมัครทุกช่องทางตรงกันทั้งหมด |
| **Basic Flow of Events** | 1. ผู้ใช้เปิดหน้าตั้งค่ากำหนดการรับสมัคร<br>2. ระบบแสดงรายการแผนการเรียนที่เปิดรับสมัคร พร้อมสรุปกำหนดการปัจจุบันของแต่ละแผน<br>3. ผู้ใช้เลือกแผนการเรียนที่ต้องการกำหนดปฏิทิน<br>4. ผู้ใช้ระบุวันเปิดและปิดรับสมัครออนไลน์ วันสอบคัดเลือก วันประกาศผล วันรายงานตัว และวันมอบตัว<br>5. ผู้ใช้ยืนยันการบันทึก<br>6. ระบบตรวจสอบว่าวันที่ทุกช่วงถูกระบุครบและเรียงลำดับก่อนหลังถูกต้อง แล้วบันทึกกำหนดการและแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 3a — กำหนดปฏิทินแยกตามแผนการเรียน:** ผู้ใช้ตั้งกำหนดการของแต่ละแผนการเรียนให้ต่างกันได้ ระบบเก็บปฏิทินแยกรายแผนและใช้ปฏิทินของแผนที่ผู้สมัครเลือกเป็นเกณฑ์<br><br>**Exception 6a — ระบุวันที่ไม่ครบ:** ระบบแจ้งว่ายังระบุวันที่ไม่ครบทุกช่วง และไม่บันทึกจนกว่าจะครบ<br><br>**Exception 6b — ลำดับวันที่ไม่ถูกต้อง:** หากลำดับก่อนหลังของวันที่ขัดแย้งกัน เช่น วันปิดรับสมัครอยู่ก่อนวันเปิดรับสมัคร ระบบแจ้งเตือนพร้อมระบุคู่วันที่ที่ขัดแย้งและไม่บันทึกจนกว่าจะแก้ไข |

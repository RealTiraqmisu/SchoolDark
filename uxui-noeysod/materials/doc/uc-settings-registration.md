# Use Case Description — หมวดที่ 4: การตั้งค่างานทะเบียนนักเรียน

หมวดนี้ครอบคลุมการตั้งค่าที่รองรับงานทะเบียนนักเรียน ได้แก่ ฟอร์มข้อมูลนักเรียนและคอลัมน์ที่แสดงในรายการทะเบียน

> Actor, Stakeholder และกฎธุรกิจร่วม (`BR-xx`) ดูที่ [`use-case-description-index.md`](./use-case-description-index.md)

---

## UC-SET-REG-01 ตั้งค่าฟอร์มนักเรียน

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ตั้งค่าฟอร์มนักเรียน |
| **ID** | UC-SET-REG-01 |
| **Scenario** | ฝ่ายทะเบียนพบว่าเวลาบันทึกนักเรียนย้ายเข้าระหว่างเทอม เจ้าหน้าที่มักลืมระบุเลขประจำตัวประชาชนและอีเมลผู้ปกครอง ซึ่งจำเป็นต่อการออกเอกสารและการแจ้งเตือน จึงต้องปรับให้สองรายการนี้เป็นข้อมูลบังคับในฟอร์มข้อมูลนักเรียน ขณะเดียวกันก็ปลดล็อกข้อมูลสุขภาพให้ไม่บังคับ เพราะบางรายยังไม่มีใบรับรองแพทย์ตอนย้ายเข้า |
| **Trigger Event** | ฝ่ายทะเบียนต้องการเปลี่ยนแปลงข้อมูลที่ต้องเก็บจากนักเรียน หรือปรับระดับความจำเป็นของข้อมูลในฟอร์มประวัตินักเรียน |
| **Brief Description** | กำหนดว่าข้อมูลใดในฟอร์มประวัตินักเรียนเป็นข้อมูลที่จำเป็นต้องระบุ โดยครอบคลุมหมวดข้อมูลเดียวกับที่ใช้เก็บประวัตินักเรียนทั้งระบบ ได้แก่ ประวัติส่วนตัว ที่อยู่ ข้อมูลบิดามารดาและผู้ปกครอง ข้อมูลการศึกษา ข้อมูลสุขภาพ และหลักฐานประกอบ |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | เกี่ยวข้องกับ UC-REG-01 จัดการข้อมูลนักเรียนและศิษย์เก่า — การเพิ่มนักเรียนและการนำเข้าข้อมูลใช้เกณฑ์ความจำเป็นจากการตั้งค่านี้<br>เกี่ยวข้องกับ UC-REG-03 แก้ไขข้อมูลนักเรียน — ฟอร์มแก้ไขแสดงเครื่องหมายบังคับตามค่าที่ตั้งไว้<br>คล้ายกับ UC-SET-ADM-01 ตั้งค่าฟอร์มรับสมัครนักเรียน — ใช้โครงหมวดข้อมูลชุดเดียวกัน แต่คนละบริบทการใช้งาน |
| **Stakeholders** | นักเรียน, ผู้ปกครอง, ครูประจำชั้น, นายทะเบียน, ฝ่ายวิชาการ |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. ระบบมีโครงข้อมูลตั้งต้นของฟอร์มข้อมูลนักเรียนครบทุกหมวด |
| **Post-Conditions** | 1. ค่าความจำเป็นของแต่ละข้อมูลถูกบันทึกลงระบบ<br>2. ฟอร์มเพิ่มนักเรียนและฟอร์มแก้ไขข้อมูลนักเรียนแสดงเครื่องหมายบังคับตามค่าที่ตั้งไว้ใหม่<br>3. การตรวจความครบถ้วนก่อนบันทึกข้อมูลนักเรียนใช้เกณฑ์ชุดใหม่ทันที<br>4. การเปลี่ยนแปลงไม่ย้อนหลังไปกระทบข้อมูลนักเรียนที่บันทึกไว้ก่อนหน้า |
| **Basic Flow of Events** | 1. ผู้ใช้เปิดหน้าตั้งค่าฟอร์มข้อมูลนักเรียน<br>2. ระบบแสดงหมวดข้อมูลทั้งหมด ตั้งแต่ประวัติส่วนตัว ที่อยู่ ข้อมูลบิดามารดาและผู้ปกครอง ข้อมูลการศึกษา ข้อมูลสุขภาพ ไปจนถึงหลักฐานประกอบ<br>3. ผู้ใช้เลือกหมวดข้อมูลที่ต้องการปรับ<br>4. ระบบแสดงรายการข้อมูลของหมวดนั้นพร้อมสถานะความจำเป็นปัจจุบัน<br>5. ผู้ใช้กำหนดว่าข้อมูลใดจำเป็นต้องระบุหรือไม่จำเป็น<br>6. ผู้ใช้ยืนยันการบันทึกการตั้งค่า<br>7. ระบบบันทึกค่าทั้งหมดลงระบบและแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 6a — คืนค่าเดิม:** ผู้ใช้เลือกคืนค่าเดิมแทนการบันทึก ระบบทิ้งการเปลี่ยนแปลงที่ยังไม่ได้บันทึกและโหลดค่าที่บันทึกไว้ล่าสุดกลับมาแสดง<br><br>**Exception 5a — พยายามปลดข้อมูลที่ระบบต้องใช้เป็นแกนหลัก:** หากผู้ใช้พยายามปลดความจำเป็นของข้อมูลแกนหลักที่ระบบต้องใช้เสมอ เช่น ชื่อและนามสกุล ระบบแจ้งว่าข้อมูลนี้เป็นข้อมูลบังคับของระบบและปรับเปลี่ยนไม่ได้<br><br>**Exception 6a — บันทึกไม่สำเร็จ:** ระบบแจ้งข้อผิดพลาดและคงค่าที่ผู้ใช้ปรับไว้บนหน้าจอ เพื่อให้บันทึกซ้ำได้โดยไม่ต้องตั้งค่าใหม่ |

## UC-SET-REG-02 ตั้งค่าคอลัมน์นักเรียน

| หัวข้อ | รายละเอียด |
|---|---|
| **Use Case Name** | ตั้งค่าคอลัมน์นักเรียน |
| **ID** | UC-SET-REG-02 |
| **Scenario** | ฝ่ายทะเบียนพบว่ารายการทะเบียนนักเรียนไม่แสดงเกรดเฉลี่ยสะสมและแผนการเรียน ซึ่งต้องใช้บ่อยตอนจัดห้องเรียนใหม่ ส่วนคอลัมน์วันที่เข้าเรียนแทบไม่ได้ใช้เลย จึงต้องปรับคอลัมน์ในรายการทะเบียนใหม่ และเพิ่มคอลัมน์เบอร์โทรผู้ปกครองที่ยังไม่มีในระบบ |
| **Trigger Event** | ผู้ใช้ต้องการปรับคอลัมน์ที่แสดงในรายการทะเบียนนักเรียน เพิ่มคอลัมน์ใหม่ ซ่อนคอลัมน์ที่ไม่ได้ใช้ หรือเปลี่ยนลำดับการแสดงผล |
| **Brief Description** | กำหนดว่ารายการทะเบียนนักเรียนจะแสดงคอลัมน์ใดบ้าง เรียงลำดับอย่างไร คอลัมน์ใดเป็นคอลัมน์หลักที่ใช้เปิดรายละเอียดนักเรียน รวมถึงการเพิ่มคอลัมน์ใหม่โดยผูกกับข้อมูลที่มีอยู่ |
| **Actor(s)** | ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary) |
| **Related Use Cases** | «include» UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า — รายการทะเบียนเรนเดอร์คอลัมน์ตามค่าที่ตั้งไว้ที่นี่<br>เกี่ยวข้องกับ UC-REG-06 ส่งออกรายชื่อนักเรียน — รายการคอลัมน์ที่เลือกส่งออกได้มาจากค่าที่ตั้งไว้ที่นี่<br>ต่างจาก UC-SET-REG-01 ตั้งค่าฟอร์มนักเรียน — Use Case นี้ตั้งค่าการแสดงผลในรายการ ไม่ใช่ฟอร์มกรอกข้อมูล |
| **Stakeholders** | ครูประจำชั้น, ครู, นายทะเบียน, ฝ่ายวิชาการ |
| **Pre-Conditions** | 1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม<br>2. ระบบมีชุดคอลัมน์มาตรฐานของรายการทะเบียนนักเรียนอยู่แล้ว<br>3. ต้องมีคอลัมน์หลักอยู่หนึ่งคอลัมน์เสมอ |
| **Post-Conditions** | 1. ค่าคอนฟิกคอลัมน์ถูกบันทึกลงระบบทันทีในทุกการดำเนินการ<br>2. รายการทะเบียนนักเรียนแสดงเฉพาะคอลัมน์ที่เปิดไว้ เรียงตามลำดับที่กำหนด<br>3. คอลัมน์หลักที่กำหนดไว้ใช้เปิดรายละเอียดนักเรียนได้ และไม่สามารถซ่อนได้<br>4. การส่งออกข้อมูลนำรายการคอลัมน์ชุดเดียวกันไปเป็นตัวเลือกให้ผู้ใช้<br>5. การลบคอลัมน์มีผลเฉพาะการแสดงผล ข้อมูลของนักเรียนแต่ละคนไม่ถูกลบ |
| **Basic Flow of Events** | 1. ผู้ใช้เปิดหน้าตั้งค่าคอลัมน์นักเรียน<br>2. ระบบแสดงรายการคอลัมน์ทั้งหมด พร้อมสถานะการแสดงผลและลำดับปัจจุบัน<br>3. ผู้ใช้กำหนดว่าคอลัมน์ใดจะแสดงในรายการหรือไม่<br>4. ผู้ใช้ปรับลำดับการแสดงผลของคอลัมน์ตามต้องการ<br>5. ผู้ใช้เลือกเพิ่มคอลัมน์ใหม่<br>6. ผู้ใช้ระบุชื่อคอลัมน์ ข้อมูลที่จะผูก และการจัดวางข้อความ<br>7. ผู้ใช้ยืนยันการบันทึก<br>8. ระบบตรวจสอบข้อมูล เพิ่มคอลัมน์ใหม่ และแจ้งผลสำเร็จ |
| **Alternate/Exception Flows** | **Alt Flow 3a — ตั้งคอลัมน์หลัก:** ผู้ใช้เลือกคอลัมน์ที่ต้องการเป็นคอลัมน์หลัก ระบบถอดสถานะจากคอลัมน์เดิม กำหนดคอลัมน์ใหม่เป็นคอลัมน์หลัก และบังคับเปิดการแสดงผลให้อัตโนมัติ<br><br>**Alt Flow 5a — แก้ไขหรือลบคอลัมน์เดิม:** ผู้ใช้เลือกแก้ไขคอลัมน์ที่มีอยู่ หรือเลือกลบคอลัมน์ที่ไม่ใช่คอลัมน์มาตรฐานของระบบ คอลัมน์มาตรฐานแก้ไขได้เฉพาะชื่อที่แสดง<br><br>**Alt Flow 2a — คืนค่าเริ่มต้น:** ผู้ใช้เลือกคืนค่าคอลัมน์ทั้งหมดกลับเป็นค่ามาตรฐานของระบบ<br><br>**Exception 3a — พยายามซ่อนคอลัมน์หลัก:** ระบบแจ้งว่าคอลัมน์หลักซ่อนไม่ได้ และให้ตั้งคอลัมน์อื่นเป็นคอลัมน์หลักก่อนหากต้องการซ่อนคอลัมน์นี้<br><br>**Exception 7a — ข้อมูลคอลัมน์ใหม่ไม่ครบถ้วน:** ระบบแจ้งว่ายังไม่ได้ระบุชื่อคอลัมน์ และไม่บันทึกจนกว่าจะกรอกครบ |

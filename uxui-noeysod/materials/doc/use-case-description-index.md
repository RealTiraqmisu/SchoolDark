## มุมมองของเอกสารนี้

เอกสารชุดนี้บรรยายระบบตามที่ออกแบบไว้ (as-designed) ในระดับการวิเคราะห์ความต้องการ — บอกว่า
*ระบบทำอะไร* เพื่อบรรลุเป้าหมายของแต่ละ Actor ไม่ใช่รายละเอียดว่าหน้าจอมีหน้าตาอย่างไรหรือพัฒนาไว้แค่ไหน

## Actor

| Actor | ประเภท | ขอบเขตการใช้งาน |
|---|---|---|
| ผู้ดูแลระบบ (System Administrator) | Primary | ทุก Use Case |
| ฝ่ายทะเบียน / เจ้าหน้าที่ทะเบียน (Registrar) | Primary | ทุก Use Case |
| ครู (Teacher) | Primary | ดูข้อมูลนักเรียน และส่งออกรายชื่อ/รายงาน (UC-REG-02, UC-REG-06, UC-REG-07) |
| ครูประจำชั้น (Homeroom Teacher) | Primary | ดูและแก้ไขข้อมูล **เฉพาะนักเรียนในห้องที่ตนรับผิดชอบ** (UC-REG-02, UC-REG-03) |
| ผู้สมัคร / ผู้ปกครอง (Applicant / Guardian) | Primary (ของหมวด UC-APP) | ยื่นใบสมัครออนไลน์ (UC-APP-01), ตรวจสอบสถานะและยืนยันสิทธิ์การเข้าศึกษา (UC-APP-02) |
| ระบบอีเมล (Mail Service) | Secondary (External) | ส่งอีเมลแจ้งเตือนถึงผู้ปกครอง (UC-ADM-04) |
| ระบบพิมพ์เอกสาร (Print / Export Service) | Secondary (External) | สร้างไฟล์เอกสารและสั่งพิมพ์ (UC-REG-06, UC-REG-07, UC-REG-08, UC-ADM-05) |
| ระบบ REGIS สช. | Secondary (External) | รับข้อมูลนักเรียนจากสถานศึกษา (UC-REG-06) |
| ระบบชำระเงิน (Payment Service) | Secondary (External) | รับการชำระค่าสมัครสอบจากผู้สมัคร (UC-APP-02) |

### Stakeholders ที่อ้างถึงบ่อย

ผู้อำนวยการโรงเรียน, ฝ่ายวิชาการ, นักเรียน, ผู้ปกครอง, นายทะเบียน, หน่วยงานต้นสังกัด (สพฐ. / สช.)

## กฎทางธุรกิจร่วม (Global Business Rules)

กฎเหล่านี้ใช้ร่วมกันหลาย Use Case จึงประกาศไว้ที่นี่ครั้งเดียว แล้วอ้างถึงด้วยรหัส `BR-xx`

| รหัส | กฎ |
|---|---|
| **BR-01** | **รหัสใบสมัคร** ระบบออกให้อัตโนมัติเมื่อส่งใบสมัครสำเร็จ ประกอบด้วยปีการศึกษาและลำดับ |
| **BR-02** | **รหัสนักเรียน** ระบบออกให้อัตโนมัติเมื่อสถานะเปลี่ยนเป็น "กำลังศึกษา / มอบตัวเสร็จสิ้น" เท่านั้น ก่อนหน้านั้นนักเรียนยังไม่มีรหัสนี้ |
| **BR-03** | **สถานะมี 14 แบบ** แบ่งเป็นช่วงรับสมัคร 9 สถานะ และหลังมอบตัว 5 สถานะ (ดูตารางด้านล่าง) |
| **BR-04** | **ศิษย์เก่าไม่ใช่ข้อมูลคนละชุด** — ศิษย์เก่าคือนักเรียนที่มีสถานะ "สำเร็จการศึกษา" อยู่ในทะเบียนเดียวกัน |
| **BR-05** | **ย้ายห้องเรียนได้เฉพาะภายในระดับชั้นเดียวกัน** การเปลี่ยนระดับชั้นต้องใช้ Use Case เลื่อนชั้นเท่านั้น |
| **BR-06** | **การเลื่อนชั้นเป็นแบบยกเว้นเฉพาะราย** — นักเรียนที่กำลังศึกษาทุกคนเลื่อนชั้นโดยปริยาย ผู้ใช้เลือกยกเว้นเฉพาะรายที่ไม่ผ่านเกณฑ์ |
| **BR-07** | **นักเรียนชั้นสุดท้ายของแต่ละช่วงชั้นที่ผ่านการเลื่อนชั้นจะเปลี่ยนสถานะเป็น "สำเร็จการศึกษา"** ไม่ใช่เลื่อนไประดับถัดไป |
| **BR-08** | **ระบบต้องแจ้งให้ผู้ใช้ทราบเสมอว่าคำสั่งที่กำลังจะดำเนินการมีผลกับข้อมูลชุดใดและจำนวนเท่าใด** ก่อนที่ผู้ใช้จะยืนยันดำเนินการ |
| **BR-09** | **เมื่อผู้ใช้สั่งการที่ยังดำเนินการไม่ได้ ระบบต้องแจ้งเหตุผลที่ทำไม่ได้และเงื่อนไขที่ต้องทำก่อน** ไม่ปฏิเสธคำสั่งโดยไม่อธิบาย |
| **BR-10** | **ทุกการส่งออก พิมพ์ หรือบันทึกการเปลี่ยนแปลงแบบกลุ่ม ต้องมีขั้นตอนตรวจสอบตัวอย่างผลลัพธ์ก่อนยืนยัน** เสมอ |
| **BR-11** | **โครงห้องเรียนของโรงเรียน** = ม.1–ม.6 ระดับชั้นละ 5 ห้อง รวม 30 ห้อง ใช้ชุดเดียวกันทั้งระบบ |
| **BR-12** | **ห้องเรียนจริงของนักเรียน** ยึดค่าที่บันทึกไว้เป็นหลัก หากยังไม่เคยบันทึก จึงคำนวณจากแผนการเรียน |
| **BR-13** | **การแสดงข้อมูลส่วนบุคคลต้องเป็นไปตาม PDPA** — เลขประจำตัวประชาชนแสดงแบบปิดบังเป็นค่าเริ่มต้น ผู้ใช้เปิดดูได้เมื่อต้องการ |

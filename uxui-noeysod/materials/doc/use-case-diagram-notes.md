## 2. Actor ทั้งหมดที่ต้องมีใน Diagram

**Primary Actor (วางฝั่งซ้ายของ system boundary)**

1. ผู้ดูแลระบบ
2. เจ้าหน้าที่ทะเบียน / ฝ่ายทะเบียน
3. ครู
4. ครูประจำชั้น
5. ผู้สมัคร หรือ ผู้ปกครอง — วางแยกกลุ่มไว้ต่างหาก เพราะเป็นบุคคลภายนอกสถานศึกษา

**Secondary Actor (วางฝั่งขวาของ system boundary)**

1. ระบบอีเมล
2. ระบบพิมพ์เอกสาร
3. ระบบ REGIS สช.
4. ระบบชำระเงิน

**ความสัมพันธ์ระหว่าง Actor:** ครูประจำชั้นเป็น generalization ของครู (ครูประจำชั้นคือครูที่มีสิทธิ์เพิ่ม)
วาดเส้นลูกศรหัวสามเหลี่ยมโปร่งจากครูประจำชั้นไปหาครู

## 4. เส้น «include» ที่ต้องวาด

```
UC-REG-03  ──«include»──▶  UC-REG-02
UC-REG-04  ──«include»──▶  UC-REG-02
UC-REG-05  ──«include»──▶  UC-REG-02
UC-REG-06  ──«include»──▶  UC-REG-02
UC-REG-07  ──«include»──▶  UC-REG-02
UC-REG-08  ──«include»──▶  UC-REG-02
UC-ADM-02  ──«include»──▶  UC-ADM-01
UC-ADM-03  ──«include»──▶  UC-ADM-01
UC-ADM-04  ──«include»──▶  UC-ADM-01
UC-ADM-05  ──«include»──▶  UC-ADM-01
UC-SET-REG-02  ──«include»──▶  UC-REG-02
```

ลูกศรประ หัวลูกศรเปิด ชี้จาก base use case ไปยัง use case ที่ถูกรวมเข้ามา เพราะทุกงานที่ทำกับรายชื่อ
นักเรียนหรือผู้สมัครต้องผ่านการค้นหาและเลือกรายการก่อนเสมอ

---

## 5. เส้น «extend» ที่ต้องวาด

```
UC-APP-02  ──«extend»──▶  UC-APP-01     (ติดตามผลหลังยื่นใบสมัคร)
UC-APP-02  ──«extend»──▶  UC-ADM-03     (ผู้สมัครทำให้สถานะเปลี่ยนได้ด้วยตนเอง)
UC-ADM-04  ──«extend»──▶  UC-ADM-03     (แจ้งผลหลังเปลี่ยนสถานะ)
UC-ADM-04  ──«extend»──▶  UC-ADM-02     (ติดตามเอกสารที่ยังขาด)
UC-REG-08  ──«extend»──▶  UC-REG-04     (ออกเอกสารให้ผู้สำเร็จการศึกษา)
```

ลูกศรประ หัวลูกศรเปิด ชี้จาก use case ที่ขยาย ไปยัง base use case

## 6. ข้อควรระวังทางหลักการ

1. **ห้ามลากเส้น «include» ไปหา Use Case หมวดตั้งค่า** (UC-SET-ADM-xx, UC-SET-REG-xx) —
   การพึ่งพาค่าที่ตั้งไว้เป็น Pre-Condition ไม่ใช่ include ตามหลัก UML ถ้าต้องการแสดงความเชื่อมโยง
   ให้ใช้ note แนบไว้แทน หรือไม่วาดเส้นเลย
2. **ห้ามวาด Use Case หมวดตั้งค่าเป็นวงย่อยของ Use Case หลัก** — เป็น Use Case ระดับเดียวกันที่มี
   Actor และเป้าหมายของตัวเอง
3. **ไม่ควรมีเส้นเกิน 15 เส้นในหนึ่ง diagram** — ถ้าแน่นเกินไป ให้แยกเป็น 2 diagram คือฝั่งงานรับสมัคร
   (UC-APP + UC-ADM + UC-SET-ADM) กับฝั่งงานทะเบียน (UC-REG + UC-SET-REG) แล้วอ้างอิงถึงกันด้วย note
4. **Actor ผู้สมัคร/ผู้ปกครองต้องไม่มีเส้นเชื่อมเข้า Use Case หมวดงานทะเบียนนักเรียนเลย** เพราะงานทะเบียน
   เป็นงานภายในของสถานศึกษาทั้งหมด

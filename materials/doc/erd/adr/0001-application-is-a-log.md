# ใบสมัครเป็น log ไม่ย้ายประวัติผู้สมัครไปไว้ที่ person

อาจารย์ทัก (2026-11-05) ว่าประวัติที่ผูกกับ `application` น่าจะย้ายไปที่ `person` และแนะนำว่าคนเดิมสมัครหลายรอบควรใช้ข้อมูลเดิม โดยยืนยันตัวด้วยเลขบัตร/OTP เราเลือกให้ `application` เก็บข้อมูลผู้สมัครครบในใบเอง เป็น log ของ ณ วันที่ยื่น แล้วทำให้ผู้สมัครซ้ำไม่ต้องกรอกใหม่ด้วยการให้ระบบดึงใบล่าสุดมาเติมให้หลังยืนยันเลขบัตร + OTP ส่วนตัวบุคคลจริงเกิดตอนมอบตัวที่ `student` เท่านั้น

เหตุผล: ถ้าเก็บที่ตัวบุคคลกลาง ผู้สมัครที่กลับมาสมัครรอบใหม่จะทับข้อมูลของใบเก่า (เช่น สมัคร ม.1 ปี 2569 GPAX 3.20 แล้วสมัคร ม.4 ปี 2572 GPAX 3.80 ใบปี 2569 จะกลายเป็น 3.80) ซึ่งผิดความจริงของใบนั้น การเป็น log ทำให้ใบเก่าคงเดิมโดยไม่ต้องสร้างกลไกเก็บประวัติเพิ่ม

## Considered Options

- **ย้ายทั้งหมดไป person** (ที่อาจารย์แนะนำ): ไม่ต้องกรอกซ้ำโดยธรรมชาติ แต่ใบเก่าถูกทับ และต้องมีตารางประวัติการศึกษาแยกมาแก้
- **แบ่งครึ่ง** (ที่อยู่/ผู้ปกครอง/สุขภาพไป person, GPAX/โรงเรียนเดิมอยู่ใบ): ยังต้องมีตัวบุคคลกลางตั้งแต่ตอนสมัคร และคนที่ไม่ได้มอบตัวจะค้างเป็น person
- **คงที่ใบ + ผูก person_id ถ้าเป็นนักเรียนอยู่แล้ว**: ใช้ได้ แต่ซ้อนกับการหา student ด้วยเลขบัตรตอนมอบตัวอยู่แล้ว จึงไม่จำเป็น

## Consequences

- `application` ไม่มี `person_id` ตารางลูก address / guardian / health / document / status_history ยังชี้ `application_id`
- ข้อมูลเดียวกันของผู้สมัครคนเดียวจะซ้ำกันได้ในหลายใบ ยอมรับเพราะเป็นบันทึกประวัติ
- ต้องมีกลไกหาใบล่าสุดจากเลขบัตร (ตอนสมัครซ้ำ) ซึ่งเลขบัตรในใบสมัครจึงต้องมี index แต่ห้ามเป็น UK
- ตอนมอบตัว ต้องมีขั้น "หา student เดิมด้วยเลขบัตร ถ้าเจอใช้แถวเดิม ถ้าไม่เจอสร้างใหม่"
- ต้องมีเหตุผลนี้ไว้ตอบอาจารย์เพราะตรงข้ามกับที่ท่านแนะนำ

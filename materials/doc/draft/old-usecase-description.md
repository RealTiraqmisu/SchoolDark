ตารางที่ 3.1 UC-ADM-01 จัดการข้อมูลผู้สมัคร
Use Case Name	จัดการข้อมูลผู้สมัคร	ID: UC-ADM-01
Brief Description	เจ้าหน้าที่ทะเบียนสามารถค้นหา เรียกดูรายละเอียด แก้ไข และลบข้อมูลผู้สมัครที่ยื่นเข้ามาในระบบตลอดกระบวนการคัดเลือก
Actor(s)	ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary)
Stakeholders	ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, นายทะเบียน
Pre-Conditions	1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีข้อมูลผู้สมัครอยู่ในระบบอย่างน้อย 1 ราย
Post-Conditions	1. ข้อมูลผู้สมัครที่ค้นหาแสดงผลถูกต้องตรงตามเงื่อนไขที่ระบุ
2. ข้อมูลที่แก้ไขถูกบันทึกพร้อมประวัติผู้แก้ไขและเวลาที่แก้ไข
3. ข้อมูลที่ถูกลบจะไม่ปรากฏในระบบอีกต่อไป และไม่สามารถกู้คืนได้
Basic Flow of Events	1. เจ้าหน้าที่ทะเบียนเข้าสู่หน้ารายการผู้สมัคร
2. ระบบแสดงรายการผู้สมัครแยกตามขั้นตอนของกระบวนการคัดเลือก
3. เจ้าหน้าที่ทะเบียนค้นหาหรือกรองรายการตามชื่อ รหัสผู้สมัคร ระดับชั้น หรือแผนการเรียน
4. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครที่ต้องการดูรายละเอียด
5. ระบบแสดงประวัติและความคืบหน้าของผู้สมัครรายนั้น
6. เจ้าหน้าที่ทะเบียนเลือกแก้ไขข้อมูลและระบุข้อมูลที่ต้องการปรับปรุง
7. ระบบตรวจสอบความถูกต้องของข้อมูล บันทึกการเปลี่ยนแปลง พร้อมบันทึกผู้แก้ไขและเวลาที่แก้ไข
Alternate/Exception Flows	Alt Flow 6a ลบข้อมูลผู้สมัคร
1. เจ้าหน้าที่ทะเบียนเลือกลบข้อมูลผู้สมัครแทนการแก้ไข
2. ระบบแสดงข้อความยืนยันการลบข้อมูลและแจ้งเตือนว่าไม่สามารถกู้คืนได้
3. เจ้าหน้าที่ทะเบียนยืนยันการลบข้อมูล
4. ระบบลบข้อมูลออกจากระบบพร้อมบันทึกประวัติการดำเนินการ

Exception 3a ไม่พบข้อมูลตามเงื่อนไข
ระบบแจ้งว่าไม่พบผู้สมัครที่ตรงกับเงื่อนไขการค้นหา และแนะนำให้ปรับเงื่อนไขใหม่

Exception 7a ข้อมูลที่จำเป็นไม่ครบถ้วน
ระบบแจ้งเตือนว่ายังกรอกข้อมูลบังคับไม่ครบถ้วน และจะไม่บันทึกข้อมูลจนกว่าจะได้รับการแก้ไขให้ถูกต้อง

ตารางที่ 3.2 UC-ADM-02 พิจารณาเอกสารผู้สมัคร
Use Case Name	พิจารณาเอกสารผู้สมัคร	ID: UC-ADM-02
Brief Description	เจ้าหน้าที่ทะเบียนตรวจสอบความครบถ้วนและความถูกต้องของเอกสารหลักฐานที่ผู้สมัครแนบมา พร้อมบันทึกผลการพิจารณาเพื่อใช้เป็นเงื่อนไขในการอนุมัติสิทธิ์เข้าสอบและแจ้งเตือนผู้ปกครอง
Actor(s)	ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary)
Stakeholders	ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, นายทะเบียน
Pre-Conditions	1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีรายการผู้สมัครที่แนบเอกสารหลักฐานเรียบร้อยแล้วในระบบ
3. มีการกำหนดรายการเอกสารที่ต้องใช้ไว้ล่วงหน้า
Post-Conditions	1. ผลการพิจารณาเอกสารของผู้สมัคร (ครบถ้วนหรือไม่ครบถ้วน) ถูกบันทึกลงสู่ระบบ
2. สถานะเอกสารในหน้ารายการผู้สมัครและหน้ารายละเอียดผู้สมัครได้รับการอัปเดตให้สอดคล้องกันทันที
3. ผู้สมัครที่เอกสารไม่ครบถูกรวมเป็นกลุ่มเป้าหมายสำหรับการแจ้งเตือน
Basic Flow of Events	1. เจ้าหน้าที่ทะเบียนเปิดรายการผู้สมัครในขั้นตอนแรกของกระบวนการคัดเลือก
2. ระบบแสดงสถานะความครบถ้วนของเอกสารของผู้สมัครแต่ละราย
3. เจ้าหน้าที่ทะเบียนเลือกดูเอกสารที่แนบมาของผู้สมัครรายหนึ่ง
4. ระบบแสดงรายการเอกสารที่ผู้สมัครแนบไว้พร้อมสถานะการอัปโหลดของแต่ละรายการ
5. เจ้าหน้าที่ทะเบียนตรวจสอบเอกสารแต่ละรายการ
6. เจ้าหน้าที่ทะเบียนบันทึกผลการพิจารณาว่าเอกสารครบถ้วนหรือไม่ พร้อมระบุรายการที่ขาด
7. ระบบบันทึกผล และปรับสถานะเอกสารที่แสดงในรายการผู้สมัครและรายละเอียดผู้สมัคร
Alternate/Exception Flows	Alt Flow 6a พิจารณาเอกสารหลายรายพร้อมกัน
1. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครหลายรายพร้อมกัน
2. เจ้าหน้าที่ทะเบียนบันทึกผลการพิจารณาเอกสารให้กับกลุ่มผู้สมัครที่เลือก
3. ระบบบันทึกผลและปรับสถานะเอกสารของผู้สมัครทุกรายในกลุ่ม

Alt Flow 7a แจ้งผู้ปกครองให้ส่งเอกสารเพิ่ม
1. หลังบันทึกผลว่าเอกสารไม่ครบถ้วน เจ้าหน้าที่ทะเบียนเลือกกลุ่มผู้สมัครดังกล่าว
2. เจ้าหน้าที่ทะเบียนส่งอีเมลแจ้งเตือนการส่งเอกสารเพิ่มเติมไปยังผู้ปกครอง

Exception 3a ไม่พบข้อมูลผู้สมัคร
1. ระบบแจ้งว่าไม่พบผู้สมัครรายนั้น และไม่แสดงรายการเอกสาร

ตารางที่ 3.3 UC-ADM-03 จัดการสถานะผู้สมัคร
Use Case Name	จัดการสถานะผู้สมัคร	ID: UC-ADM-03
Brief Description	เจ้าหน้าที่ทะเบียนปรับสถานะของผู้สมัครให้สอดคล้องกับความคืบหน้าในกระบวนการคัดเลือก ทั้งแบบรายบุคคลและแบบกลุ่ม พร้อมบันทึกคะแนนสอบ โดยมีการยืนยันก่อนดำเนินการทุกครั้งและรองรับการย้อนกลับรายการ
Actor(s)	ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary)
Stakeholders	ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, ฝ่ายวิชาการ, ฝ่ายการเงิน, ผู้อำนวยการโรงเรียน
Pre-Conditions	1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีผู้สมัครที่จะเปลี่ยนสถานะอยู่ในระบบ
3. คณะกรรมการรับนักเรียนอนุมัติผลการคัดเลือกเรียบร้อยแล้ว (กรณีประกาศผลสอบ)
Post-Conditions	1. ผู้สมัครมีสถานะใหม่ตามที่กำหนด และถูกจัดกลุ่มตามขั้นตอนที่ตรงกับสถานะนั้นโดยอัตโนมัติ
2. เมื่อสถานะเปลี่ยนเป็น "กำลังศึกษา" หรือ "มอบตัวเสร็จสิ้น" ระบบจะออกรหัสนักเรียนให้อัตโนมัติตาม BR-02 และปรับเปลี่ยนสถานะผู้สมัครเข้าสู่ทะเบียนนักเรียน
3. คะแนนสอบที่บันทึกปรากฏในรายละเอียดของผู้สมัครทันที
4. เจ้าหน้าที่ทะเบียนสามารถย้อนกลับการเปลี่ยนสถานะได้ทันทีหลังทำรายการ ทั้งแบบรายบุคคลและแบบกลุ่ม
Basic Flow of Events	1. เจ้าหน้าที่ทะเบียนเลือกกลุ่มผู้สมัครตามขั้นตอนของกระบวนการคัดเลือกที่ต้องการดำเนินการ
2. ระบบแสดงรายการผู้สมัครในขั้นตอนนั้น
3. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครหนึ่งรายหรือหลายรายที่ต้องการปรับสถานะ
4. เจ้าหน้าที่ทะเบียนระบุสถานะใหม่ที่ต้องการเปลี่ยน
5. ระบบแสดงรายละเอียดการเปลี่ยนแปลงให้ตรวจสอบก่อนยืนยัน รวมถึงแจ้งหากผู้สมัครจะถูกย้ายไปยังขั้นตอนอื่น
6. เจ้าหน้าที่ทะเบียนยืนยันการเปลี่ยนสถานะ
7. ระบบบันทึกสถานะใหม่ของผู้สมัครทุกรายที่เลือก แจ้งผลการดำเนินการ และแสดงตัวเลือกสำหรับการย้อนกลับรายการ
Alternate/Exception Flows	Alt Flow 7a ย้อนกลับการเปลี่ยนสถานะ
1. เจ้าหน้าที่ทะเบียนเลือกย้อนกลับรายการภายในระยะเวลาที่กำหนด
2. ระบบคืนค่าสถานะเดิมให้กับผู้สมัครทุกรายในชุดรายการนั้น

Alt Flow B บันทึกคะแนนสอบ
1. เจ้าหน้าที่ทะเบียนเลือกกรอกหรือแก้ไขคะแนนสอบของผู้สมัคร
2. เจ้าหน้าที่ทะเบียนระบุคะแนนดิบและคะแนนเฉลี่ยสะสม
3. ระบบบันทึกคะแนนโดยไม่เปลี่ยนสถานะของผู้สมัคร
4. เจ้าหน้าที่ทะเบียนดำเนินการปรับสถานะแยกต่างหากตามผลการสอบ

Exception 6a ยกเลิกก่อนยืนยัน
1. เจ้าหน้าที่ทะเบียนยกเลิกรายการก่อนยืนยัน
2. ระบบจะไม่ทำการเปลี่ยนแปลงสถานะใด ๆ

Exception B1a กรอกคะแนนไม่ครบถ้วน
1. ระบบแจ้งเตือนว่ายังกรอกคะแนนไม่ครบถ้วน และจะไม่บันทึกข้อมูลจนกว่าจะระบุครบทุกช่อง

ตารางที่ 3.4 UC-ADM-04 ส่งอีเมลถึงผู้สมัคร
Use Case Name	ส่งอีเมลถึงผู้สมัคร	ID: UC-ADM-04
Brief Description	เจ้าหน้าที่ทะเบียนจัดทำและส่งอีเมลแจ้งเตือนหรือประกาศผลไปยังผู้ปกครองของผู้สมัครที่เลือกไว้ โดยสามารถเลือกใช้แบบร่างเนื้อหาสำเร็จรูป แทรกตัวแปรข้อมูลนักเรียน แนบไฟล์เอกสาร และตรวจสอบรายชื่อผู้รับก่อนส่ง
Actor(s)	ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary) · ระบบอีเมล (Secondary) · ผู้ปกครอง (Secondary — ผู้รับปลายทาง)
Stakeholders	ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, ผู้อำนวยการโรงเรียน
Pre-Conditions	1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีรายชื่อผู้รับอย่างน้อย 1 รายที่ระบุข้อมูลอีเมลผู้ปกครองไว้ในระบบ
Post-Conditions	1. ระบบจัดส่งอีเมลไปยังผู้ปกครองของผู้สมัครตามรายชื่อผู้รับที่กำหนด
2. ตัวแปรข้อมูลนักเรียนในเนื้อหาถูกแทนที่ด้วยข้อมูลจริงของผู้รับแต่ละราย
3. ระบบบันทึกประวัติการจัดส่งอีเมล พร้อมข้อมูลจำนวนผู้รับและเนื้อหาข้อความที่ใช้
Basic Flow of Events	1. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครที่ต้องการแจ้งผล
2. ระบบเปิดหน้าแต่งอีเมลพร้อมรายชื่อผู้รับที่เลือกไว้
3. ระบบแสดงจำนวนผู้รับพร้อมข้อมูลประกอบของแต่ละราย เช่น แผนการเรียนและคะแนนสอบ
4. เจ้าหน้าที่ทะเบียนเลือกแบบร่างเนื้อหาสำเร็จรูปที่ตรงกับวัตถุประสงค์ เช่น แจ้งผลสอบผ่าน แจ้งผลสอบไม่ผ่าน แจ้งเอกสารไม่ครบถ้วน หรือแจ้งชำระค่าธรรมเนียมสมัคร
5. ระบบดึงข้อมูลหัวข้อและเนื้อหาตามแบบร่างที่เลือก โดยเจ้าหน้าที่ทะเบียนสามารถปรับแก้เพิ่มเติมและแทรกตัวแปรข้อมูลนักเรียนได้ เช่น ชื่อ-สกุล แผนการเรียน คะแนน และห้องเรียน
6. เจ้าหน้าที่ทะเบียนตรวจสอบรายชื่อผู้รับและเนื้อหาแล้วยืนยันการส่ง
7. ระบบตรวจสอบความถูกต้อง ส่งอีเมลไปยังผู้ปกครองทุกรายผ่านระบบอีเมล บันทึกประวัติการส่ง และแสดงแจ้งเตือนผลการดำเนินงานสำเร็จ
Alternate/Exception Flows	Alt Flow 1a ส่งอีเมลรายบุคคล
1. เจ้าหน้าที่ทะเบียนเลือกส่งอีเมลแจ้งผลแก่ผู้สมัครรายเดียวจากหน้ารายรายละเอียดผู้สมัคร
2. ระบบเปิดหน้าจัดทำอีเมลที่มีรายชื่อผู้รับเพียงรายเดียว

Alt Flow 4a เขียนเนื้อหาอิสระ
1. เจ้าหน้าที่ทะเบียนเลือกเขียนเนื้อหาเองแทนการใช้เนื้อหาสำเร็จรูป
2. ระบบเปิดให้ระบุหัวข้อและเนื้อหาใหม่ทั้งหมด

Exception 2a ไม่พบรายชื่อผู้รับ
1. ระบบแจ้งเตือนว่าไม่พบข้อมูลผู้รับปลายทาง
2. ระบบแนะนำให้กลับไปเลือกผู้สมัครที่ต้องการแจ้งเตือนก่อน

Exception 6a ข้อมูลที่จำเป็นไม่ครบถ้วน
1. ระบบแจ้งเตือนว่ายังไม่ได้ระบุหัวข้อหรือเนื้อหาอีเมล และจะไม่ดำเนินการส่งจนกว่าจะกรอกข้อมูลครบถ้วน

ตารางที่ 3.5 UC-ADM-05 ส่งออกใบสมัคร
Use Case Name	ส่งออกใบสมัคร	ID: UC-ADM-05
Brief Description	เจ้าหน้าที่ทะเบียนสร้างและส่งออกเอกสารของผู้สมัคร ได้แก่ ใบสมัครและใบแสดงความจำนง ใบแจ้งยอดชำระเงินและหลักฐานการชำระค่าธรรมเนียมสอบ รวมถึงใบรายงานตัวมอบตัวและข้อมูลห้องเรียน โดยมีขั้นตอนแสดงตัวอย่างเอกสารให้ตรวจสอบก่อนดำเนินการจริง
Actor(s)	ผู้ดูแลระบบ, เจ้าหน้าที่ทะเบียน (Primary) · ระบบพิมพ์เอกสาร (Secondary)
Stakeholders	ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, ฝ่ายการเงิน, นายทะเบียน
Pre-Conditions	1. เจ้าหน้าที่ทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีรายชื่อผู้สมัครที่ต้องการออกเอกสารอย่างน้อย 1 รายในระบบ
Post-Conditions	1. ระบบสร้างเอกสารตามชนิดที่เลือกให้ผู้สมัครทุกรายในขอบเขตที่กำหนด
2. เจ้าหน้าที่ทะเบียนได้รับไฟล์เอกสารที่สร้างขึ้น หรือระบบส่งคำสั่งพิมพ์ไปยังเครื่องพิมพ์เรียบร้อยแล้ว
3. ระบบบันทึกประวัติการออกเอกสาร
Basic Flow of Events	1. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครรายบุคคลหรือกลุ่มผู้สมัครที่ต้องการสร้างเอกสาร
2. เจ้าหน้าที่ทะเบียนเลือกชนิดเอกสารที่ต้องการส่งออก (ใบสมัคร/ใบแจ้งยอด/ใบมอบตัว)
3. ระบบสร้างตัวอย่างเอกสารพร้อมดึงข้อมูลผู้สมัครมาแสดงผลเพื่อตรวจสอบความถูกต้อง
4. เจ้าหน้าที่ทะเบียนตรวจสอบความถูกต้องของข้อมูลแล้วยืนยันการส่งออกเอกสาร
5. ระบบประมวลผลสร้างไฟล์เอกสาร (PDF) หรือส่งคำสั่งพิมพ์ไปยังเครื่องพิมพ์ พร้อมบันทึกประวัติการออกเอกสาร
Alternate/Exception Flows	Alt Flow 1a ส่งออกเอกสารเป็นกลุ่ม
1. เจ้าหน้าที่ทะเบียนเลือกผู้สมัครพร้อมกันหลายราย
2. ระบบสร้างไฟล์เอกสารรวมเป็นชุดเดียวกันสำหรับการพิมพ์หรือดาวน์โหลดในครั้งเดียว

Exception 3a ข้อมูลไม่ครบถ้วนสำหรับออกเอกสาร
1. ระบบแจ้งเตือนรายการข้อมูลหรือเอกสารแนบที่ยังไม่สมบูรณ์
2. ระบบปฏิเสธการออกเอกสารจนกว่าข้อมูลจะได้รับการแก้ไข

ตารางที่ 3.6 UC-REG-01 จัดการข้อมูลนักเรียนและศิษย์เก่า
Use Case Name	จัดการข้อมูลนักเรียนและศิษย์เก่า	ID: UC-REG-01
Brief Description	บันทึกข้อมูลนักเรียนเข้าสู่ระบบทะเบียนโดยตรงโดยไม่ผ่านกระบวนการรับสมัคร รองรับทั้งการเพิ่มรายบุคคลและการนำเข้าเป็นกลุ่มจากไฟล์ ซึ่งสามารถระบุได้ทั้งนักเรียนปัจจุบันและศิษย์เก่าในไฟล์เดียวกัน รวมถึงรองรับการลบรายการข้อมูลที่ไม่ถูกต้องออกจากระบบ
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	นักเรียน, ผู้ปกครอง, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน, หน่วยงานต้นสังกัด
Pre-Conditions	1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. ระบบมีข้อมูลโครงสร้างห้องเรียนของโรงเรียนครบถ้วนตาม BR-11 และมีแผนการเรียนอย่างน้อย 1 แผน
3. กรณีนำเข้าข้อมูลเป็นกลุ่ม เจ้าหน้าที่ทะเบียนต้องเตรียมไฟล์ข้อมูลที่มีโครงสร้างตรงตามรูปแบบที่ระบบกำหนด
Post-Conditions	1. นักเรียนใหม่ถูกบันทึกลงทะเบียนนักเรียน พร้อมรหัสใบสมัครและรหัสนักเรียนที่สร้างขึ้นให้อัตโนมัติตาม BR-01 และ BR-02
2. นักเรียนที่บันทึกผ่าน Use Case นี้มีสถานะตั้งต้นเป็น "กำลังศึกษา" ทันที โดยไม่ต้องผ่านขั้นตอนรับสมัคร
3. ข้อมูลที่นำเข้าด้วยประเภทศิษย์เก่าจะได้รับสถานะ "สำเร็จการศึกษา"
4. การดำเนินการทั้งหมดถูกบันทึกลงประวัติการใช้งาน พร้อมระบุชื่อผู้ทำรายการและวันเวลา
5. รายการทะเบียนและสถิติจำนวนนักเรียนต่อห้องเรียนได้รับการอัปเดตให้ตรงกับข้อมูลล่าสุดทันที
Basic Flow of Events	1. ฝ่ายทะเบียนเข้าสู่รายการทะเบียนนักเรียน
2. ฝ่ายทะเบียนเลือกเพิ่มนักเรียนใหม่
3. ฝ่ายทะเบียนระบุประเภทนักเรียน ระหว่างนักเรียนใหม่กับนักเรียนที่ย้ายมาจากสถานศึกษาอื่น
4. ฝ่ายทะเบียนระบุข้อมูลประวัติพื้นฐาน ระดับชั้น ห้องเรียน และแผนการเรียนของนักเรียน
5. ระบบตรวจสอบความถูกต้องของข้อมูลที่จำเป็น และแสดงสรุปข้อมูลให้ตรวจสอบก่อนยืนยัน
6. ฝ่ายทะเบียนยืนยันการเพิ่มนักเรียน
7. ระบบบันทึกข้อมูลนักเรียนลงทะเบียน ออกรหัสใบสมัครและรหัสนักเรียนให้อัตโนมัติ กำหนดสถานะเป็น "กำลังศึกษา" บันทึกประวัติการทำรายการ และแจ้งผลการบันทึกสำเร็จ
Alternate/Exception Flows	Alt Flow 3a นำเข้าข้อมูลเป็นชุดจากไฟล์
1. ฝ่ายทะเบียนเลือกนำเข้าข้อมูลนักเรียนจากไฟล์ที่มีโครงสร้างตรงตามที่กำหนด (ระบุได้ว่าเป็นนักเรียนปัจจุบันหรือศิษย์เก่า)
2. ระบบมีไฟล์แบบร่างให้ดาวน์โหลดเพื่อใช้อ้างอิง
3. เมื่อเลือกไฟล์แล้ว ระบบจะตรวจสอบความถูกต้อง
4. ระบบบันทึกข้อมูลแต่ละรายการ และแจ้งผลการนำเข้าสำเร็จ

Alt Flow 6a ลบข้อมูลนักเรียน
1. ฝ่ายทะเบียนเลือกลบข้อมูลนักเรียนออกจากระบบ
2. ระบบแสดงข้อความแจ้งเตือนว่าการลบจะยกเลิกสถานะนักเรียนอย่างถาวรและไม่สามารถกู้คืนได้
3. ฝ่ายทะเบียนยืนยันการลบข้อมูล
4. ระบบลบข้อมูล บันทึกประวัติการทำรายการ และแจ้งผลสำเร็จ

Exception 5a ข้อมูลที่จำเป็นไม่ครบถ้วน
1. ระบบแจ้งเตือนว่ายังไม่ได้ระบุชื่อและนามสกุลของนักเรียน และจะไม่บันทึกข้อมูลจนกว่าจะกรอกครบถ้วน

Exception A3a ไฟล์นำเข้าผิดรูปแบบหรือมีข้อมูลไม่ถูกต้อง
1. ระบบยกเลิกกระบวนการนำเข้า
2. ระบบแสดงรายการข้อผิดพลาดที่พบ และจะไม่บันทึกข้อมูลใด ๆ ลงระบบจนกว่าไฟล์จะได้รับการแก้ไขให้ถูกต้อง

ตารางที่ 3.7 UC-REG-02 ดูข้อมูลนักเรียนและศิษย์เก่า
Use Case Name	ดูข้อมูลนักเรียนและศิษย์เก่า	ID: UC-REG-02
Brief Description	ค้นหา กรอง เรียงลำดับ และเรียกดูรายชื่อนักเรียนทั้งโรงเรียนได้ภายในหน้าเดียว ซึ่งครอบคลุมทั้งนักเรียนปัจจุบันและศิษย์เก่า พร้อมรองรับการเรียกดูรายละเอียดเชิงลึกรายบุคคล
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครู, ครูประจำชั้น (Primary)
Stakeholders	นักเรียน, ผู้ปกครอง, ครูที่ปรึกษา, ฝ่ายวิชาการ
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบในบทบาทที่มีสิทธิ์ดูข้อมูลนักเรียน
2. ระบบมีข้อมูลนักเรียนในทะเบียนอย่างน้อย 1 รายการ
3. ครูประจำชั้นจะเห็นเฉพาะข้อมูลนักเรียนในห้องที่ตนรับผิดชอบ ส่วนครูทั่วไป ฝ่ายทะเบียน และผู้ดูแลระบบจะสามารถเข้าถึงข้อมูลได้ทั้งโรงเรียน
Post-Conditions	1. ระบบแสดงรายชื่อนักเรียนที่ตรงตามเงื่อนไขพร้อมระบุจำนวนผลลัพธ์ทั้งหมด
2. เงื่อนไขการค้นหา การเรียงลำดับ และจำนวนรายการต่อหน้าที่ตั้งไว้ล่าสุดจะถูกบันทึกเพื่อใช้ในการใช้งานครั้งถัดไป
3. ไม่มีการเปลี่ยนแปลงข้อมูลนักเรียนในระบบ เนื่องจากเป็นกระบวนการเรียกดูข้อมูลเท่านั้น
Basic Flow of Events	1. ผู้ใช้เข้าสู่หน้ารายการทะเบียนนักเรียน
2. ระบบแสดงรายการนักเรียนที่มีสถานะ "กำลังศึกษา" เป็นค่าเริ่มต้น พร้อมตั้งค่าตัวกรองตามการใช้งานล่าสุด
3. ผู้ใช้ระบุเงื่อนไขการค้นหาตามคำค้น ปีการศึกษาและภาคเรียน ระดับชั้น ห้องเรียน แผนการเรียน หรือสถานะของนักเรียน
4. ระบบกรองรายชื่อตามเงื่อนไขที่กำหนด โดยอ้างอิงข้อมูลห้องเรียนจริงของนักเรียนตาม BR-12
5. ผู้ใช้เลือกลำดับการเรียงข้อมูลตามที่ต้องการ
6. ระบบแสดงผลการค้นหา พร้อมระบุจำนวนรายการทั้งหมดและการแบ่งหน้า
7. ผู้ใช้เลือกนักเรียนรายหนึ่งเพื่อดูรายละเอียด
8. ระบบแสดงประวัติส่วนตัว ความคืบหน้าในกระบวนการคัดเลือก และข้อมูลอื่น ๆ ของนักเรียนรายนั้นโดยจัดแบ่งเป็นหมวดหมู่
Alternate/Exception Flows	Alt Flow 4a ดูรายชื่อศิษย์เก่า
1. ผู้ใช้เลือกกรองข้อมูลด้วยสถานะ "สำเร็จการศึกษา"
2. ระบบแสดงเฉพาะรายชื่อศิษย์เก่าพร้อมสรุปจำนวนรวม

Alt Flow 6a เจาะดูเฉพาะห้องเรียน
1. ผู้ใช้เลือกดูเฉพาะระดับชั้นหรือห้องเรียนใดห้องเรียนหนึ่ง
2. ระบบปรับรูปแบบการเรียงลำดับเป็นตามเลขที่ในห้องให้อัตโนมัติ
3. ระบบจะคืนค่าการเรียงลำดับเดิมเมื่อกลับมาเลือกดูภาพรวมทั้งโรงเรียน

Alt Flow 3a ล้างเงื่อนไขทั้งหมด
1. ผู้ใช้เลเลือกล้างตัวกรองทั้งหมด
2. ระบบคืนค่าเงื่อนไขการค้นหาทั้งหมดกลับเป็นค่าเริ่มต้น

Exception 6a ไม่พบข้อมูลตามเงื่อนไข
1. ระบบแสดงข้อความแจ้งว่าไม่พบข้อมูลนักเรียนที่ตรงตามเงื่อนไข พร้อมแสดงปุ่มสำหรับล้างตัวกรองทั้งหมด

ตารางที่ 3.8 UC-REG-03 แก้ไขข้อมูลนักเรียน
Use Case Name	แก้ไขข้อมูลนักเรียน	ID: UC-REG-03

Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครูประจำชั้น (Primary)
Stakeholders	นักเรียน, ผู้ปกครอง, ครูที่ปรึกษา, นายทะเบียน
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบในบทบาทผู้ดูแลระบบ ฝ่ายทะเบียน หรือครูประจำชั้น

2. นักเรียนที่จะแก้ไขมีอยู่จริงในระบบ
3. ครูประจำชั้นแก้ไขได้เฉพาะนักเรียนในห้องที่ตนรับผิดชอบ
Post-Conditions	1. ข้อมูลประวัตินักเรียนได้รับการปรับปรุงแก้ไขตามที่ระบุ

3. ข้อมูลที่แก้ไขจะได้รับการอัปเดตในหน้ารายการทะเบียน หน้ารายละเอียดนักเรียน และเอกสารที่จะส่งออกในอนาคตทันที
Basic Flow of Events	1. ผู้ใช้เลือกแก้ไขข้อมูลของนักเรียนที่ต้องการ
2. ระบบแสดงข้อมูลเดิมของนักเรียน โดยจัดกลุ่มเป็น ข้อมูลส่วนบุคคล ข้อมูลการติดต่อและผู้ปกครอง และแผนการศึกษา
3. ระบบแสดงข้อมูลสถานะแบบอ่านอย่างเดียว ประกอบด้วย รหัสประจำตัว วันเข้าเรียน ห้องเรียนปัจจุบัน ความครบถ้วนของเอกสาร และชื่อผู้แก้ไขล่าสุด
4. ผู้ใช้ปรับปรุงข้อมูลที่ต้องการแก้ไข
5. ผู้ใช้ยืนยันการบันทึก
6. ระบบตรวจสอบความถูกต้องของข้อมูลที่จำเป็น บันทึกการเปลี่ยนแปลง พร้อมประทับชื่อผู้แก้ไขและวันเวลาที่ทำรายการ แล้วแจ้งผลการบันทึกสำเร็จ
Alternate/Exception Flows	Alt Flow 3a เปิดดูเลขบัตรประจำตัวประชาชน
1. ผู้ใช้เลือกเปิดดูเลขประจำตัวประชาชนที่ปิดบังไว้ตาม BR-13
2. ระบบแสดงเลขเต็มชั่วคราวและกลับไปปิดบังเช่นเดิมเมื่อออกจากช่องข้อมูลนั้น

Alt Flow 5a ยกเลิกการแก้ไข
1. ผู้ใช้ยกเลิกรายการก่อนบันทึก
2. ระบบจะยกเลิกการเปลี่ยนแปลงทั้งหมดและกลับสู่หน้ารายการทะเบียนโดยไม่บันทึกข้อมูลใด ๆ

Exception 6a ข้อมูลที่จำเป็นไม่ครบถ้วน
1. ระบบแจ้งเตือนว่ายังกรอกข้อมูลบังคับ (ได้แก่ ชื่อ นามสกุล และอีเมลผู้ปกครอง) ไม่ครบถ้วน โดยจะคงหน้าแก้ไขไว้พร้อมข้อมูลที่กรอกไว้เดิม

Exception 1a ไม่พบข้อมูลนักเรียน
1. ระบบแจ้งเตือนว่าไม่พบข้อมูลนักเรียนในระบบ และจะไม่แสดงแบบฟอร์มแก้ไข

ตารางที่ 3.9 UC-REG-04 ย้ายห้องเรียน เลื่อนชั้นนักเรียน
Use Case Name	ย้ายห้องเรียน เลื่อนชั้นนักเรียน	ID: UC-REG-04
Brief Description	ปรับเปลี่ยนโครงสร้างชั้นเรียนของนักเรียน 2 รูปแบบ ได้แก่ การย้ายห้องเรียนภายในระดับชั้นเดียวกันและการเลื่อนระดับชั้นขึ้น 1 ปีการศึกษา พร้อมบันทึกการสำเร็จการศึกษาสำหรับนักเรียนชั้นปีสุดท้าย โดยมีขั้นตอนตรวจสอบข้อมูลสรุปและการยกเว้นรายบุคคลก่อนบันทึกจริง
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	นักเรียน, ผู้ปกครอง, ครูประจำชั้น, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน
Pre-Conditions	1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีนักเรียนสถานะกำลังศึกษาอยู่ในขอบเขตที่เลือกอย่างน้อย 1 คน
3. กรณีย้ายห้องเรียน รายชื่อนักเรียนที่เลือกจะต้องอยู่ในระดับชั้นเดียวกันทั้งหมดตาม BR-05
4. กรณีเลื่อนชั้น ผลการเรียนปลายปีการศึกษาต้องได้รับการอนุมัติจากฝ่ายวิชาการเรียบร้อยแล้ว
Post-Conditions	1. นักเรียนที่ได้รับการย้ายห้องจะเข้าสู่ห้องเรียนใหม่ตามที่ระบุ และนับรวมในยอดจำนวนนักเรียนของห้องปลายทางทันที
2. นักเรียนที่เลื่อนชั้นจะได้รับการปรับระดับชั้นสูงขึ้น 1 ระดับ โดยคงหมายเลขห้องเรียนเดิมในระดับชั้นใหม่
3. นักเรียนชั้นปีสุดท้ายของแต่ละช่วงชั้นที่ผ่านเกณฑ์ จะได้รับการปรับสถานะเป็น "สำเร็จการศึกษา" ตาม BR-07 และเข้าสู่สถานะศิษย์เก่า
4. นักเรียนที่ถูกระบุยกเว้นจะยังคงระดับชั้น ห้องเรียน และสถานะเดิมไว้
5. ระบบบันทึกประวัติการทำรายการ พร้อมสรุปจำนวนนักเรียนที่ได้รับการเลื่อนชั้น สำเร็จการศึกษา และถูกยกเว้น
Basic Flow of Events	1. ฝ่ายทะเบียนเลือกคำสั่งเลื่อนชั้นเรียนและบันทึกการสำเร็จการศึกษา
2. ระบบดึงรายชื่อนักเรียนที่มีสถานะ "กำลังศึกษา" ทั้งหมดมาเป็นรายการตั้งต้น โดยกำหนดให้เลื่อนชั้นโดยปริยายตาม BR-06
3. ฝ่ายทะเบียนตรวจสอบรายชื่อและยกเว้นเฉพาะนักเรียนที่ไม่ผ่านเกณฑ์
4. ระบบแสดงสรุปจำนวนนักเรียนที่จะได้รับการเลื่อนชั้น สำเร็จการศึกษา และถูกยกเว้นให้ตรวจสอบ
5. ฝ่ายทะเบียนยืนยันการดำเนินการ
6. ระบบปรับระดับชั้นและห้องเรียนของผู้เลื่อนชั้น เปลี่ยนสถานะผู้สำเร็จการศึกษาเป็น "สำเร็จการศึกษา" บันทึกประวัติการทำรายการ และแจ้งผลสำเร็จ
Alternate/Exception Flows	Alt Flow 1a เลื่อนชั้นเฉพาะนักเรียนที่เลือก
1. ฝ่ายทะเบียนเลือกเฉพาะนักเรียนบางส่วนจากหน้ารายการทะเบียน
2. ฝ่ายทะเบียนดำเนินการสั่งเลื่อนชั้นเฉพาะกลุ่มที่เลือกไว้

Alt Flow B ย้ายห้องเรียนภายในระดับชั้นเดียวกัน
1. ฝ่ายทะเบียนเลือกย้ายห้องเรียนแบบยกทั้งห้องหรือเฉพาะนักเรียนที่เลือก
2. ฝ่ายทะเบียนระบุห้องเรียนปลายทางในระดับชั้นเดียวกัน
3. ระบบแสดงสรุปการเปลี่ยนแปลงให้ตรวจสอบก่อนยืนยัน
4. ระบบบันทึกห้องเรียนใหม่ให้กับนักเรียน

Exception 5a ไม่มีรายชื่อที่ต้องดำเนินการ
1. หากฝ่ายทะเบียนระบุยกเว้นนักเรียนทั้งหมด ระบบจะแจ้งเตือนว่าไม่มีรายชื่อที่ต้องเลื่อนชั้นและจะไม่ดำเนินการต่อ

Exception B1a เลือกนักเรียนข้ามระดับชั้น
1. หากมีการเลือกนักเรียนจากหลายระดับชั้นพร้อมกันในการย้ายห้อง ระบบจะปฏิเสธการทำรายการ
2. ระบบแจ้งว่าเมนูนี้ใช้สำหรับการสลับห้องภายในระดับชั้นเดียวกันเท่านั้น และแนะนำให้ใช้เมนูเลื่อนชั้นเรียนหากต้องการเปลี่ยนระดับชั้น


 ตารางที่ 3.10 UC-REG-05 จัดการนักเรียนลาออก
Use Case Name	จัดการนักเรียนลาออก	ID: UC-REG-05
Brief Description	ปรับเปลี่ยนสถานะของนักเรียนที่จำหน่ายออกจากทะเบียนนักเรียนปัจจุบันออกเป็น 4 ประเภท ได้แก่ ย้ายสถานศึกษา ลาออก พักการเรียน หรือพ้นสภาพการเป็นนักเรียน พร้อมระบุข้อมูลสถานศึกษาปลายทางและเหตุผล โดยมีขั้นตอนตรวจสอบข้อมูลก่อนบันทึกจริง
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	นักเรียน, ผู้ปกครอง, ครูประจำชั้น, นายทะเบียน, โรงเรียนปลายทาง, หน่วยงานต้นสังกัด
Pre-Conditions	1. ฝ่ายทะเบียนเข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. ฝ่ายทะเบียนต้องเลือกนักเรียนจากหน้ารายการทะเบียนอย่างน้อย 1 คน
3. คำร้องขอหรือคำสั่งอนุมัติที่เกี่ยวข้องได้รับการอนุมัติจากผู้มีอำนาจเรียบร้อยแล้ว
Post-Conditions	1. นักเรียนที่เลือกได้รับการปรับเปลี่ยนสถานะใหม่ตรงตามประเภทที่ระบุ
2. ระบบบันทึกเหตุผลการพ้นสภาพ สถานศึกษาปลายทาง และวันที่มีผลบังคับใช้ไว้ในประวัติของนักเรียนแต่ละคน
3. นักเรียนที่เปลี่ยนสถานะแล้วจะถูกนำออกจากมุมมองนักเรียนกำลังศึกษา ยอดจำนวนนักเรียนในห้องเรียนลดลงตามจริง และไม่อยู่ในเกณฑ์การเลื่อนชั้นเรียน
4. ระบบบันทึกประวัติการทำรายการ พร้อมสรุปจำนวนนักเรียนและสถานะปลายทาง
Basic Flow of Events	1. ฝ่ายทะเบียนเลือกนักเรียนที่ต้องการปรับสถานะจากรายการทะเบียน
2. ระบบแสดงคำสั่งที่สามารถดำเนินการได้ พร้อมระบุจำนวนนักเรียนที่เลือกไว้
3. ฝ่ายทะเบียนเลือกคำสั่งบันทึกการย้ายออก ลาออก หรือปรับสถานะการพ้นสภาพ
4. ระบบแสดงรายชื่อนักเรียนที่จะดำเนินการ โดยฝ่ายทะเบียนสามารถปรับลดรายชื่อก่อนบันทึกได้
5. ฝ่ายทะเบียนระบุประเภทการจำหน่ายออก (ย้ายไปสถานศึกษาอื่น ลาออก พักการเรียน หรือพ้นสภาพ) พร้อมระบุสถานศึกษาปลายทางและเหตุผลประกอบ
6. ระบบแสดงสรุปข้อมูลการเปลี่ยนแปลงทั้งหมดให้ตรวจสอบก่อนยืนยัน
7. ฝ่ายทะเบียนยืนยันการดำเนินการ
8. ระบบบันทึกสถานะใหม่ เหตุผล สถานศึกษาปลายทาง และวันที่มีผล พร้อมบันทึกประวัติการทำรายการ และแสดงแจ้งเตือนผลสำเร็จ
Alternate/Exception Flows	Alt Flow 5a ตัดบางคนออกจากรายการ
1. ฝ่ายทะเบียนนำรายชื่อนักเรียนบางคนออกจากรายการที่จะดำเนินการก่อนยืนยัน
2. ระบบจะปรับคำนวณยอดจำนวนที่จะดำเนินการให้ตรงตามรายการที่เหลือ

Exception 1a ยังไม่ได้เลือกนักเรียน
1. ระบบแจ้งเตือนว่าต้องเลือกนักเรียนอย่างน้อย 1 คนก่อนจึงจะสามารถทำรายการได้

Exception 7a ไม่มีนักเรียนเหลือในรายการ
1. หากฝ่ายทะเบียนลบรายชื่อนักเรียนออกจากรายการจนหมด ระบบจะแจ้งเตือนว่าไม่มีนักเรียนที่จะดำเนินการและจะไม่บันทึกข้อมูลใด ๆ

ตารางที่ 3.11 UC-REG-06 ส่งออกรายชื่อนักเรียน
Use Case Name	ส่งออกรายชื่อนักเรียน	ID: UC-REG-06
Brief Description	ส่งออกรายชื่อนักเรียนเป็นไฟล์ผ่านขั้นตอนเดียว โดยเลือกปรับตั้งค่าได้ทั้งประเภทข้อมูล ขอบเขตที่จะส่งออก คอลัมน์ที่ต้องการแสดง และรูปแบบไฟล์ รวมถึงรองรับการพิมพ์บัตรประจำตัวนักเรียนและการส่งข้อมูลไปยังระบบของหน่วยงานต้นสังกัด
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน, ครู (Primary) · ระบบพิมพ์เอกสาร, ระบบ REGIS สช. (Secondary)
Stakeholders	ครูประจำชั้น, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน, หน่วยงานต้นสังกัด
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบในบทบาทที่มีสิทธิ์เข้าถึงข้อมูลนักเรียน
2. มีข้อมูลนักเรียนตรงตามขอบเขตที่เลือกอย่างน้อย 1 รายในระบบ
3. ต้องเลือกคอลัมน์ที่จะแสดงผลอย่างน้อย 1 คอลัมน์
Post-Conditions	1. ระบบสร้างไฟล์ตามรูปแบบและเงื่อนไขที่กำหนด พร้อมส่งไฟล์ให้ผู้ใช้ดาวน์โหลด
2. เนื้อหาในไฟล์ตรงตามขอบเขต คอลัมน์ และการเรียงลำดับที่ตรวจสอบในขั้นตอนแสดงตัวอย่าง
3. ระบบบันทึกประวัติการส่งออกข้อมูล พร้อมระบุประเภทข้อมูล ขอบเขต และรูปแบบไฟล์
4. ไม่มีการเปลี่ยนแปลงข้อมูลนักเรียนในระบบ
Basic Flow of Events	1. ผู้ใช้กรองรายชื่อนักเรียนในหน้ารายการทะเบียนให้ได้กลุ่มเป้าหมายที่ต้องการ
2. ผู้ใช้เลือกคำสั่งส่งออกข้อมูล
3. เจ้าหน้าที่ระบุประเภทข้อมูล ขอบเขตของนักเรียน คอลัมน์ที่ต้องการแสดง และรูปแบบไฟล์ที่จะส่งออก
4. ระบบแสดงตัวอย่างข้อมูลจริงตามที่กำหนดไว้ให้ตรวจสอบก่อนยืนยัน
5. ผู้ใช้ยืนยันการส่งออก
6. ระบบสร้างไฟล์ตามเงื่อนไขที่กำหนด ส่งไฟล์ให้ผู้ใช้ดาวน์โหลด บันทึกประวัติการส่งออก และแจ้งผลสำเร็จ
Alternate/Exception Flows	Alt Flow B พิมพ์บัตรประจำตัวนักเรียน
1. ผู้ใช้เลือกพิมพ์บัตรประจำตัวนักเรียนของกลุ่มที่กำหนด

3. ระบบบันทึกประวัติการออกรายงานสถิติ
4. ไม่มีการเปลี่ยนแปลงข้อมูลนักเรียนในระบบ

2. ระบบประมวลผลคำนวณจากฐานข้อมูลนักเรียนและแสดงตารางสถิติแยกตามระดับชั้นและสถานะ
3. ผู้ใช้เลือกพิมพ์รายงานสรุป
4. ระบบแสดงตัวอย่างรายงานให้ตรวจสอบก่อนยืนยัน
5. ผู้ใช้ยืนยันการพิมพ์
6. ระบบสร้างรายงาน ส่งคำสั่งพิมพ์ไปยังระบบพิมพ์เอกสาร บันทึกประวัติการทำรายการ และแจ้งผลสำเร็จ

1. ผู้ใช้เลือกส่งออกรายงานเฉพาะเรื่องแทนการพิมพ์รายงานสรุปภาพรวม

3. ระบบจะคัดกรองข้อมูลตามช่วงเวลาดังกล่าวแล้วแสดงตัวอย่างก่อนส่งออกเป็นไฟล์

Exception 3a ไม่พบข้อมูลในช่วงเวลาที่เลือก

2. มีรายชื่อนักเรียนตรงตามกลุ่มเป้าหมายและระดับชั้นที่เลือกอย่างน้อย 1 คน

4. ฝ่ายทะเบียนปรับรายชื่อทีละคนได้ตามต้องการ
5. ระบบแสดงตัวอย่างเอกสารให้ตรวจสอบก่อนยืนยัน

Exception 3a ไม่มีนักเรียนตรงตามเงื่อนไข

4. ระบบแสดงรายการฟิลด์ข้อมูลของหมวดนั้น ๆ พร้อมสถานะความจำเป็นปัจจุบัน

6. ผู้ใช้ยืนยันการบันทึกการตั้งค่า
7. ระบบบันทึกการตั้งค่าทั้งหมดลงฐานข้อมูลและแสดงแจ้งเตือนผลสำเร็จ

Exception 8a ที่นั่งไม่เพียงพอกับจำนวนผู้สมัคร

Use Case Name	ตั้งค่าและจัดการกำหนดการรับสมัคร	ID: UC-SET-ADM-03
Brief Description	กำหนดและปรับปรุงปฏิทินการรับสมัครของแต่ละแผนการเรียน ครอบคลุมช่วงเวลาสำคัญ ได้แก่ วันเปิด-ปิดรับสมัครออนไลน์ วันสอบคัดเลือก วันประกาศผล วันรายงานตัว และวันมอบตัว เพื่อให้ระบบและผู้สมัครใช้อ้างอิงกำหนดการชุดเดียวกัน
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	ผู้สมัคร, ผู้ปกครอง, คณะกรรมการรับนักเรียน, ฝ่ายวิชาการ, ผู้อำนวยการโรงเรียน
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีข้อมูลแผนการเรียนที่จะเปิดรับสมัครอยู่ในระบบแล้ว
3. ปฏิทินการรับสมัครได้รับการอนุมัติจากคณะกรรมการรับนักเรียนเรียบร้อยแล้ว
Post-Conditions	1. กำหนดการทุกช่วงถูกบันทึกไว้กับแผนการเรียนที่เกี่ยวข้อง
2. ระบบรับสมัครออนไลน์จะเปิดรับใบสมัครเฉพาะในช่วงวันที่กำหนดเปิดและปิดรับสมัครของแผนการเรียนนั้น ๆ
3. ระบบตรวจสอบสถานะผู้สมัครจะแสดงกำหนดการสอบ ประกาศผล และรายงานตัวมอบตัวตามค่าที่ตั้งไว้
4. กำหนดการที่แสดงต่อผู้ใช้งานในทุกช่องทางสอดคล้องกันทั้งหมด
Basic Flow of Events	1. ผู้ใช้เปิดหน้าตั้งค่ากำหนดการรับสมัคร
2. ระบบแสดงรายการแผนการเรียนที่เปิดรับสมัคร พร้อมสรุปกำหนดการปัจจุบันของแต่ละแผน
3. ผู้ใช้เลือกแผนการเรียนที่ต้องการกำหนดปฏิทิน
4. ผู้ใช้ระบุวันเปิด-ปิดรับสมัครออนไลน์ วันสอบคัดเลือก วันประกาศผล วันรายงานตัว และวันมอบตัว
5. ผู้ใช้ยืนยันการบันทึก
6. ระบบตรวจสอบว่ามีการระบุวันที่ครบทุกช่วงและเรียงลำดับก่อนหลังถูกต้อง แล้วบันทึกกำหนดการและแจ้งผลสำเร็จ
Alternate/Exception Flows	Alt Flow 3a กำหนดปฏิทินแยกตามแผนการเรียน
1. ผู้ใช้ตั้งกำหนดการของแต่ละแผนการเรียนให้แตกต่างกันได้
2. ระบบจะจัดเก็บปฏิทินแยกรายแผนและใช้อ้างอิงตามแผนที่ผู้สมัครเลือก

Exception 6a ระบุวันที่ไม่ครบถ้วน
1. ระบบแจ้งเตือนว่ายังระบุวันที่ไม่ครบทุกช่วง และจะไม่บันทึกจนกว่าจะกรอกครบถ้วน

Exception 6b ลำดับวันที่ไม่ถูกต้อง
1. หากลำดับก่อนหลังของวันที่ขัดแย้งกัน (เช่น วันปิดรับสมัครอยู่ก่อนวันเปิดรับสมัคร) ระบบจะแสดงแจ้งเตือนพร้อมระบุคู่วันที่ขัดแย้งและจะไม่บันทึกข้อมูลจนกว่าจะแก้ไขให้ถูกต้อง

ตารางที่ 3.17 UC-SET-ADM-04 ตั้งค่าข้อมูลอาคารและห้อง
Use Case Name	ตั้งค่าข้อมูลอาคารและห้อง	ID: UC-SET-ADM-04
Brief Description	จัดการข้อมูลหลักของอาคารและห้องเรียนในสถานศึกษา ได้แก่ ชื่อห้อง อาคาร ชั้นที่ตั้ง และความจุที่นั่ง เพื่อใช้เป็นฐานข้อมูลกลางสำหรับการจัดห้องสอบและการบริหารจัดการพื้นที่ในระบบ
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	ฝ่ายอาคารสถานที่, ฝ่ายวิชาการ, คณะกรรมการคุมสอบ, ผู้อำนวยการโรงเรียน
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. มีข้อมูลอาคารและผังห้องเรียนจริงของสถานศึกษาสำหรับใช้อ้างอิง
Post-Conditions	1. ข้อมูลห้องใหม่ถูกบันทึกลงระบบ และปรากฏเป็นตัวเลือกในการจัดห้องสอบทันที
2. จำนวนความจุที่นั่งที่ปรับปรุงใหม่ถูกนำไปใช้คำนวณที่นั่งสอบและประมวลผลคำแนะนำแผนจัดห้องสอบ
3. ห้องเรียนที่ถูกลบหรือปิดใช้งานจะไม่ปรากฏเป็นตัวเลือกในการจัดห้องสอบครั้งถัดไป
Basic Flow of Events	1. ผู้ใช้เปิดหน้าตั้งค่าข้อมูลอาคารและห้อง
2. ระบบแสดงรายการห้องทั้งหมดในสถานศึกษา พร้อมข้อมูลอาคาร ชั้น และความจุที่นั่ง
3. ผู้ใช้เลือกเพิ่มห้องใหม่
4. ผู้ใช้ระบุชื่อห้อง อาคาร ชั้น และความจุที่นั่ง
5. ผู้ใช้ยืนยันการบันทึก
6. ระบบตรวจสอบความถูกต้อง บันทึกห้องใหม่ และแจ้งผลสำเร็จ
Alternate/Exception Flows	Alt Flow 3a แก้ไขหรือลบข้อมูลห้อง
1. ผู้ใช้เลือกแก้ไขรายละเอียดห้องที่มีอยู่ หรือเลือกลบห้องออกจากระบบ
2. กรณีลบห้อง ระบบจะแจ้งจำนวนห้องสอบที่ผูกกับห้องนั้น ๆ ก่อนให้ยืนยัน

Exception 5a ข้อมูลไม่ครบถ้วนหรือไม่ถูกต้อง
1. ระบบแจ้งเตือนว่ายังไม่ได้ระบุชื่อห้อง หรือระบุความจุที่นั่งไม่ถูกต้อง และจะไม่บันทึกจนกว่าจะแก้ไขให้ถูกต้อง

Exception 5b ชื่อห้องซ้ำ
1. ระบบแจ้งเตือนว่ามีชื่อห้องนี้บันทึกอยู่อยู่แล้วในอาคารเดียวกัน และจะไม่บันทึกข้อมูลซ้ำซ้อน

Use Case Name	ตั้งค่าฟอร์มนักเรียน	ID: UC-SET-REG-01
Brief Description	กำหนดเงื่อนไขความจำเป็นของฟิลด์ข้อมูลในแบบฟอร์มบันทึกประวัตินักเรียน โดยครอบคลุมหมวดหมู่ข้อมูลเดียวกันทั้งระบบ ได้แก่ ประวัติส่วนตัว ที่อยู่ ข้อมูลผู้ปกครอง ข้อมูลการศึกษา ข้อมูลสุขภาพ และหลักฐานประกอบ
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	นักเรียน, ผู้ปกครอง, ครูประจำชั้น, นายทะเบียน, ฝ่ายวิชาการ
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. ระบบมีโครงสร้างฟิลด์ข้อมูลตั้งต้นของฟอร์มประวัตินักเรียนครบถ้วนทุกหมวด
Post-Conditions	1. ค่าตั้งค่าความจำเป็นของแต่ละฟิลด์ข้อมูลถูกบันทึกลงสู่ระบบ
2. ฟอร์มเพิ่มนักเรียนและฟอร์มแก้ไขข้อมูลนักเรียนแสดงสัญลักษณ์บังคับตามค่าการตั้งค่าใหม่
3. การตรวจสอบความครบถ้วนของข้อมูลก่อนบันทึกประวัตินักเรียนจะใช้เกณฑ์ชุดใหม่ทันที
4. การเปลี่ยนแปลงการตั้งค่าไม่มีผลย้อนหลังกระทบถึงข้อมูลนักเรียนที่บันทึกไว้ก่อนหน้า
Basic Flow of Events	1. ผู้ใช้เปิดหน้าตั้งค่าฟอร์มข้อมูลนักเรียน
2. ระบบแสดงหมวดข้อมูลทั้งหมด ได้แก่ ประวัติส่วนตัว ที่อยู่ ข้อมูลบิดามารดาและผู้ปกครอง ข้อมูลการศึกษา ข้อมูลสุขภาพ และเอกสารหลักฐานประกอบ
3. ผู้ใช้เลือกหมวดข้อมูลที่ต้องการปรับ
4. ระบบแสดงรายการฟิลด์ข้อมูลในหมวดนั้น ๆ พร้อมสถานะความจำเป็นปัจจุบัน
5. ผู้ใช้กำหนดสถานะความจำเป็นของแต่ละฟิลด์ข้อมูล (จำเป็นต้องระบุ หรือ ไม่จำเป็น)
6. ผู้ใช้ยืนยันการบันทึกการตั้งค่า
7. ระบบบันทึกค่าการตั้งค่าทั้งหมดลงฐานข้อมูลและแจ้งผลสำเร็จ
Alternate/Exception Flows	Alt Flow 6a คืนค่าเดิม
1. ผู้ใช้เลือก คืนค่าเดิม แทนการบันทึก
2. ระบบจะยกเลิกการเปลี่ยนแปลงที่ยังไม่ได้บันทึก และดึงค่าการตั้งค่าล่าสุดกลับมาแสดงผล

Exception 5a พยายามปลดฟิลด์แกนหลักของระบบ
1. หากผู้ใช้พยายามยกเลิกความจำเป็นของฟิลด์ข้อมูลหลักที่ระบบจำเป็นต้องใช้ (เช่น ชื่อและนามสกุล) ระบบจะแสดงข้อความแจ้งเตือนว่าเป็นข้อมูลบังคับของระบบและไม่สามารถปิดได้

Exception 6a บันทึกไม่สำเร็จ
1. ระบบแสดงข้อความแจ้งเตือนข้อผิดพลาด โดยจะยังคงค่าที่ผู้ใช้ปรับไว้บนหน้าจอเพื่อให้สามารถกดบันทึกซ้ำได้

Use Case Name	ตั้งค่าคอลัมน์นักเรียน	ID: UC-SET-REG-02
Brief Description	กำหนดการแสดงผลคอลัมน์ในตารางรายการทะเบียนนักเรียน เช่น การเลือกคอลัมน์ที่จะแสดง การจัดลำดับคอลัมน์ การกำหนดคอลัมน์หลักสำหรับกดเข้าดูรายละเอียดนักเรียน รวมถึงการเพิ่มคอลัมน์ใหม่โดยผูกเข้ากับฟิลด์ข้อมูลที่มีอยู่ในระบบ
Actor(s)	ผู้ดูแลระบบ, ฝ่ายทะเบียน (Primary)
Stakeholders	ครูประจำชั้น, ครู, นายทะเบียน, ฝ่ายวิชาการ
Pre-Conditions	1. ผู้ใช้เข้าสู่ระบบด้วยสิทธิ์ที่เหมาะสม
2. ระบบมีชุดคอลัมน์มาตรฐานสำหรับรายการทะเบียนนักเรียนเรียบร้อยแล้ว
3. มีการกำหนดคอลัมน์หลักไว้เสมออย่างน้อย 1 คอลัมน์
Post-Conditions	1. การตั้งค่าคอนฟิกคอลัมน์ถูกบันทึกลงสู่ระบบทันทีเมื่อทำรายการ
2. ตารางรายการทะเบียนนักเรียนแสดงเฉพาะคอลัมน์ที่เปิดใช้งาน และเรียงลำดับตามที่กำหนด
3. คอลัมน์หลักที่กำหนดสามารถใช้กดเพื่อเปิดดูหน้ารายละเอียดนักเรียนได้ และไม่สามารถซ่อนการแสดงผลได้
4. คอลัมน์ที่ตั้งค่าไว้จะถูกนำไปใช้เป็นตัวเลือกคอลัมน์ในกระบวนการส่งออกข้อมูล
5. การลบคอลัมน์จะมีผลเฉพาะการแสดงผลตาราง โดยไม่กระทบหรือลบข้อมูลจริงของนักเรียนในฐานข้อมูล

2. ระบบแสดงรายการคอลัมน์ทั้งหมด พร้อมสถานะการเปิด/ปิดแสดงผล และลำดับการแสดงผลปัจจุบัน
3. ผู้ใช้เลือกเปิดหรือปิดการแสดงผลของแต่ละคอลัมน์ในตาราง
4. ผู้ใช้ปรับลำดับการแสดงผลของคอลัมน์ตามต้องการ
5. ผู้ใช้เลือกเพิ่มคอลัมน์ใหม่เพิ่มเติม
6. ผู้ใช้ระบุชื่อคอลัมน์ ฟิลด์ข้อมูลที่จะผูกโยง และการจัดวางตำแหน่งข้อความ
7. ผู้ใช้ยืนยันการบันทึก
8. ระบบตรวจสอบความถูกต้อง เพิ่มคอลัมน์ใหม่ บันทึกการตั้งค่า และแจ้งผลสำเร็จ
Alternate/Exception Flows	Alt Flow 3a ตั้งคอลัมน์หลัก
1. ผู้ใช้เลือกกำหนดคอลัมน์ที่ต้องการให้เป็นคอลัมน์หลัก
2. ระบบจะปลดสถานะจากคอลัมน์เดิม กำหนดคอลัมน์ใหม่เป็นคอลัมน์หลักแทน และบังคับเปิดการแสดงผลให้อัตโนมัติ

2. คอลัมน์มาตรฐานของระบบจะสามารถแก้ไขได้เฉพาะชื่อที่ใช้แสดงผลเท่านั้น

Exception 3a พยายามซ่อนคอลัมน์หลัก
1. หากผู้ใช้พยายามปิดการแสดงผลคอลัมน์หลัก ระบบจะแจ้งเตือนว่าไม่สามารถซ่อนได้ และแนะนำให้เปลี่ยนคอลัมน์อื่นเป็นคอลัมน์หลักก่อน

Exception 7a ข้อมูลคอลัมน์ใหม่ไม่ครบถ้วน
1. ระบบแจ้งเตือนว่ายังไม่ได้ระบุชื่อคอลัมน์ และจะไม่บันทึกจนกว่าจะกรอกข้อมูลครบถ้วน

Actor(s)	เจ้าหน้าที่บุคคล (Primary), ผู้ดูแลระบบ
Stakeholders	บุคลากรในโรงเรียน, ผู้บริหารโรงเรียน

Post-Conditions	1. ระบบแสดงข้อมูลบุคลากรที่ผู้ใช้เลือก

4. ผู้ใช้เลือกบุคลากรที่ต้องการ
5. ระบบแสดงรายละเอียด เช่น ประวัติส่วนตัว การศึกษา ตำแหน่งงาน

Stakeholders	บุคลากรเจ้าของแฟ้ม, ผู้บริหารโรงเรียน, สำนักงานเขตพื้นที่การศึกษา

Post-Conditions	1. ได้เอกสารแฟ้มประวัติฯ ที่พร้อมพิมพ์หรือบันทึกเป็น PDF

4. ระบบแสดงตัวอย่างก่อนพิมพ์
5. ผู้ใช้กดพิมพ์หรือบันทึกเป็น PDF
